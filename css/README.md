# CSS の管理

> リポジトリ全体の構造と注意点は、ルートの `AI_HANDOFF.md` を先に読んでください。

`style.css` が長くなったため、先頭側を `css/` フォルダに分割しています。

## 重要：読み込み順が見た目に影響します

CSS は「後ろに書いたルールが前のルールを上書きする」ため、ファイルの順番を入れ替えると見た目が変わります。
分割は **元の順番をそのまま保って** 区切っただけです（6ファイルを順に連結すると、分割前の `style.css` と完全に一致します）。

`index.html` では、次の順に読み込んでいます。

| 順 | ファイル | 内容 |
|---|---|---|
| 1 | `css/01-battle-base.css` | 戦闘画面の土台：固定枠、演出（敵の登場・撃破・ステージ名）、ユニオンカットイン、ダメージ表示 |
| 2 | `css/02-screens-and-shell.css` | 共通の外枠、ショップ・装備、素材・製作、図鑑・イベント記録、実績、倍速モード |
| 3 | `css/03-responsive-layout.css` | 全画面レイアウト統一・レスポンシブ対応 |
| 4 | `css/04-nav-and-battle-panels.css` | 上部ナビのコンパクト化、コマンド欄・ログ欄の配置 |
| 5 | `css/05-progression-and-boss.css` | HP表示・ドロップ報酬、強化・育成、スキルツリー、魔王専用の表示、撤退確認 |
| 6 | `style.css` | 最後に読み込む：チュートリアル、メニュー、STORY演出、管理画面 |

## 編集のルール

1. 見た目を直したいときは、まず該当するファイルを探して、**そのファイルの中で** 直す。
2. 「前のファイルの指定を上書きしたい」ときは、**より後ろのファイル** に書く。迷ったら `style.css` の末尾に追加する。
3. ファイルを追加・改名・並べ替えたときは、`index.html` の `<link>` の順番も合わせて直す。
4. 新しい画面や機能のスタイルは、既存ファイルを伸ばすより、`css/` に新しいファイルを足して `style.css` の直前で読み込むと、他のAIとぶつかりにくい。
5. 大きな整理（重複の統合、古いルールの削除）は、見た目に影響しやすいので、専用のPRで行い、各画面のスクリーンショットを比較して確認する。

## 既知の事情

- 古いルールを最終ルールで打ち消している箇所が多く（例：`03-responsive-layout.css` と `04-nav-and-battle-panels.css`）、同じ要素のルールが複数のファイルにまたがっています。調べるときは、`.クラス名` を `css/` と `style.css` の全体で検索してください。
