# 戦闘UI刷新：現行コード調査結果（2026-11-10）

## 確認した実コード
- `script.js` 冒頭は `const PARTY_LIMIT = 4;`。以前の「最大5人」は現在の development コードと一致しない。参加人数の変更は独立案件として検討。
- `index.html` の戦闘DOMには `#battle-enemy`, `#event-log`, `#battle-party`, `#battle-commands`, `#command-description`, `#battle-result` が存在。
- `index.html` は `battle-formation-ext.js` と `css/14-battle-formation.css` を読み込む。
- `battle-formation-ext.js` には職業IDで前衛・後衛を分類する `REAR_IDS` がある。ユーザー指定の任意編成位置と同義ではない。
- `css/14-battle-formation.css` は `.battle-member[data-row]` に前衛・後衛の装飾を適用する。
- 既存のイベントログはパーティー欄より前のDOMにあり、画像案と順序が異なる。

## 未実装の要件
- 右側の立ち絵とユニオンゲージの常設表示
- 前衛3枠・後衛3枠への編成操作（最大参加人数とは別）
- 行動消費を伴う編成位置入れ替え
- 左側6コマンドとユニオン技名だけのサブメニュー
- イベント欄の下に独立した説明欄

## 実装順
1. 既存4人パーティーのまま、前後列の表示順を変える描画レイヤーを作る。
2. 立ち絵・ユニオンゲージを既存のデータから読み取り専用で表示。
3. 既存コマンドのイベントハンドラーを再利用し、左側メニューを構成。
4. 任意の前後列保存と移動ターン消費は、戦闘ロジックの担当者との競合を確認して実装。
5. テスト：戦闘開始、全コマンド、スキル・ユニオン、勝敗、リロード、セーブ復元、スマホ。

**この調査ではゲーム動作の修正・テストはしていない。** 仕様上の希望と現行実装を分けて記録する。
