# Claude担当仕様書：戦闘状態・演出トリガー連携

対象プロジェクト：kotama-no-bouken  
担当：Claude  
関連資料：同フォルダの README.md、REF-01～REF-03  
役割：戦闘ロジック側の状態管理・イベント発火・UI担当への連携仕様

## 1. 担当範囲

Claudeは、表示演出そのもののCSS・アニメーション・画像レイアウトを主担当しない。既存戦闘処理を調査し、演出側が正しいタイミングで表示できるよう、状態とイベントの接続を担当する。

### 1-1. 状態異常データの連携
- プレイヤー各キャラクターの現在の状態異常を、UIから参照できる形で確認・整理する。
- 状態異常の付与・継続・解除タイミングを既存ロジックに沿って明確化する。
- UI側が状態異常別の背景色を選べるよう、状態異常の識別子を統一する。
- 状態異常解除時に、UIへ通常状態への復帰を通知できること。
- 状態異常の効果・発生率・継続ターン数など、ゲームバランスは変更しない。

### 1-2. インペリアル蓄積状態の連携
- 既存コード内のインペリアルに相当する蓄積値・条件・消費処理を調査する。
- 現在値・最大値・消費後の値をUI側が取得できるようにする。
- 表示はSP攻撃コマンドタグ右側の縦線本数で行う前提とする。
- 専用ゲージや新しい蓄積システムは作らない。
- 既存仕様が見つからない、または定義が曖昧な場合は独自に補完せず、実装前に報告する。

### 1-3. ターン・バトルログイベント
- ターン開始・行動開始・攻撃・スキル・状態異常・回復・ターン終了のイベント発生箇所を調査する。
- 画面上部のログ表示に必要なイベント情報を整理する。
- ログ文言や戦闘結果を変えず、表示側が順番とタイミングを扱えるようにする。
- 既存のバトルログ保存仕様（現ターン・前ターン等）があれば維持する。

### 1-4. 攻撃・ユニオンスキル演出トリガー
- 通常攻撃、SP攻撃、魔法、敵特殊攻撃、ユニオンスキルについて、演出開始・命中・ダメージ確定のタイミングを特定する。
- 演出側が攻撃種別・攻撃者・対象・属性・ダメージ結果を受け取れるよう、必要最小限のイベント情報を整理する。
- ユニオンスキルは実際の参加者一覧を演出側へ渡す。
- 演出のためにダメージ計算や行動順を変更しない。
- 表示待ちによって戦闘ロジックが二重実行されないようにする。

## 2. 他担当との境界

- Claude：戦闘状態、データ、イベント発火、既存ロジックとの整合性。
- GPT：カットイン、キャラクター表示、背景色、ターン・ログUI、攻撃エフェクトなど視覚表現。
- 画像素材担当：REF-02の方向性に沿ったオリジナルキャラクター画像・演出素材の準備。

共通インターフェースが必要な場合、Claudeは先にイベント名・データ形式・発火タイミングを文書化してGPTへ共有する。相手担当のファイルを独断で大幅変更しない。

## 3. 禁止事項・維持事項

- ダメージ計算、命中率、SP増減、行動順、スキル効果、敵AI、状態異常の効果を変更しない。
- セーブデータ形式・互換性を壊さない。
- 指定外の画面・機能を変更しない。
- 既存処理の削除や置換は、必要性と影響範囲を先に報告する。

## 4. 完了報告

次を分けて報告する。
1. 調査で確認した既存仕様
2. 実装した状態・イベント連携
3. GPT側が利用するイベント名・データ形式・発火タイミング
4. 動作確認済み項目
5. 未確認・未対応項目
6. 変更ファイル一覧

## 5. 受け入れ条件

- 状態異常の付与・解除が既存戦闘処理と一致する。
- インペリアルの既存蓄積・消費仕様が変わらない。
- ターン・ログ情報が既存の戦闘結果と一致する。
- 攻撃・ユニオンスキルの演出トリガーが実際の行動と一致する。
- 演出待ちによる二重行動・二重ダメージが発生しない。
