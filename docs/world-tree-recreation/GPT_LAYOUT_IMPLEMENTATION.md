# GPT担当：世界樹の迷宮型・迷宮画面／地図UI実装仕様

- 担当：GPT
- 親仕様：`MASTER_SPEC.md`
- 優先順位：最優先。Claudeの戦闘ロジック作業よりも、まず探索画面のレイアウトと世界樹らしい地図体験を優先する。
- 対象：画面構成、レイアウト、CSS、地図描画の表示層、探索HUD、凡例、情報提示。
- 原則：ゲームルール・敵AI・セーブデータの構造は変更しない。

## 1. 必須の設計目標

**世界樹の迷宮の地図画面を参考に、プレイヤー自身が迷宮を踏破し、地図を見て次の行動を考えるUIを再現する。**

雰囲気だけの装飾ではなく、地図の読みやすさ・情報の階層・操作の速さを最優先する。現行の探索画面を確認し、既存PR #66〜#91の未統合変更も調べてから、重複しない差分を作る。

## 2. 実装対象（3項目ずつ進める）

### A. 探索画面のレイアウト再設計
- 地図を主役にする。探索画面で最も重要な情報が小さく埋もれないようにする。
- 地図、探索フィールド、階層／フロア名、座標／向き、危険情報、操作ボタンの視線順を整理する。
- ミニマップと全体マップを同じ情報の縮小版にしない。ミニマップは即時判断、全体マップは踏破計画・記録確認に役割を分ける。
- スマートフォンでは操作部を押しやすく、地図の表示面積を確保。PCでは横幅を無駄にせず地図・フィールド・情報欄を整える。
- 既存のボタン・機能・キーボード操作を削除しない。

### B. 地図の視認性・記号体系
- 床、壁、通路、扉、開いた扉、隠し通路（発見後のみ）、階段、宝箱、採集点、イベント、FOEを一貫した記号で表す。
- 壁は床との境界が明確で、通行可能／不可能を一目で区別できるようにする。
- 閉じた扉・開いた扉・鍵付き扉を形状でも区別する。
- 隠し通路は未発見時に地図上へ表示しない。発見時のみ専用記号と短い発見フィードバックを表示する。
- FOEは巡回中・追跡中・視界外の既知位置を混同しない。未発見FOEの情報を表示しない。
- 現在視界、視認済み、踏破済み、未踏を色だけでなく明度・パターン・線種でも識別可能にする。
- 既存の階層テーマ色は維持しつつ、記号の意味は階層間で統一する。

### C. 探索情報と操作性
- 現在座標・向き・階層・フロアを明瞭に表示する。
- プレイヤーが正面に向いている対象、調べられる対象、未発見の対象を誤認しないようにする。
- 地図の凡例は短く、常時表示する情報と詳細表示を分ける。
- 地図の拡大・縮小・全体表示・閉じる操作は押しやすく、画面端に寄せすぎない。
- 重要情報がログや装飾に埋もれないようにする。

## 3. 世界樹らしさの具体的な表現要件
- 地図は「冒険者が自分で記録した地図」として一貫した見た目にする。地図の記号・壁線・扉・階段・採集点・FOE表示は同じ記号体系で統一。
- 未踏領域を自動で完成地図として見せない。探索して得た情報だけが地図に残る。
- 迷宮の構造が読み取れるよう、壁と通路の境界・分岐・袋小路・扉の位置を明瞭にする。
- 地図の情報密度を上げても、スマホで文字や記号が潰れないようにする。
- 画面全体を装飾で埋めず、地図を読むための余白とコントラストを確保する。
- 既存の上部HUD・地図パネル・探索フィールドの重複表示を整理する。

## 4. 変更してよい範囲
- `css/06-field.css`、`css/07-labyrinth.css`、関連画面CSS
- 地図やHUDの表示用HTML
- `field.js` の描画・表示処理（既存の探索状態を読み取るだけの変更）
- CSSキャッシュ参照の更新（自分のPRで変更するファイルに限る）

## 5. 原則変更しない範囲
- マップ生成・マップ配列・座標の意味
- 通行判定・壁衝突・扉開閉条件・隠し通路発見判定
- 視界半径・LOS・FOEの視認距離・移動・追跡・接触判定
- 宝箱・採集の報酬や取得処理
- セーブデータ形式・固定ID・戦闘計算
- Claudeが担当するゲームロジックのファイル・作業ブランチ

表示に必要な情報が既存データに存在しない場合、仮の値や未発見情報を作らず、Claudeへ必要なデータ項目を依頼する。

## 6. 実装・報告ルール
- 3項目程度のまとまりで作業し、長い作業は区切って報告する。
- まず既存画面・コード・PR差分を調査し、重複を避ける。
- 一度に全CSSを大規模に書き換えない。既存デザインと機能を維持しながら段階的に改善する。
- ブラウザ／実機テストは実施しない。コード上の確認とユーザー側で必要な確認事項を分ける。
- 変更ファイル、変更内容、未対応、競合リスク、テスト状況をPRに記載する。
- Draft PRで提出し、ユーザー承認前にマージしない。

## 7. 完了条件
- 地図が探索画面の主役として十分な大きさと視認性を持つ。
- ミニマップと全体マップの役割が明確。
- 壁・床・扉・隠し通路・階段・宝箱・採集点・FOEが誤認なく判別できる。
- 現在視界と踏破記録、未踏領域の区別が明確。
- 未発見情報を表示しない。
- PC・スマートフォンの双方で操作情報が隠れない。
- 既存の移動・探索・セーブ・戦闘処理を壊していない。
