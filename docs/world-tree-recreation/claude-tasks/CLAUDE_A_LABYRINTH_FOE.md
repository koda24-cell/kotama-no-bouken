## 2. 実装ステップ（3項目ずつ。各ステップ終了時に報告）

### ステップA1：通行判定と扉・隠し通路の整理
1. **グリッド移動の確定**：1入力＝1マス。移動先タイルの通行可否を `fieldCanEnter(a, tx, ty, who)` に一本化（プレイヤー／FOE共通。FOE側は安全地帯の扱いを引数で切替）。壁越し・閉扉の通過が起きないこと。
2. **扉の状態モデル**：`#45` の door を拡張し、`state: "closed" | "open" | "locked"`、`oneWay`（片側からのみ開く＝ショートカット扉）、`requires`（鍵アイテム・フラグ）を持てるようにする。既存5つの仕掛けの挙動・フラグ名は変えない。
3. **隠し通路の発見ルール**：未発見の隠し通路は壁と完全に同じ扱い（描画・ミニマップ・視界・HUD・ログ・踏破率の分母に漏らさない）。正面の壁を「調べる」で発見。ヒント（ひび・看板など）はマップ側で任意に置ける。発見後は通行可・地図に記録。
   - 世界樹らしい探索の厚みのため、**各階層に1か所以上のショートカット（片側扉 or 隠し通路）**を追加する案を作り、ユーザーに提示してから入れる（マップ文字列の変更は到達性検証とセット）。

### ステップA2：FOE AI を「観察して避けられる」ルールに
1. **ターン制化**：FOE の時間はプレイヤーの1歩ごとに1ターン進む。`performance.now()` による追跡解除・猶予を**歩数（ターン）基準**に置き換える（例：見失って3ターンで巡回へ戻る、逃走後3ターン停止）。止まって考えられること。
2. **行動パターンの型**を FOE 定義（`data/field-maps.js` の `foes[]`）に追加：
   - `type: "patrol"`（経路を順に巡回。2地点以上の `path`、往復 or 周回）
   - `type: "stationary"`（その場で向きだけ変える／門番）
   - `type: "chaser"`（発見すると追跡、見失うと最後に見た地点を確認してから戻る）
   - `type: "wanderer"` は使う場合も規則性を持たせる（完全ランダム禁止）
   - 向き `dir` と視野（前方○マス・左右の扱い）を持たせ、**背後から抜けられる**等の判断材料を作る。既存の距離4.5＋見通しは「前方視野」の上限として残す。
   - 状態：`patrol / chase / search（見失い直後）/ return`。
3. **衝突と移動規則**：FOE同士は同じマスに入らない。FOEは階段・出口・ボス門・導きの灯・NPC・宝箱・採集点のマスに入らない。移動順は「プレイヤー移動 → FOE移動 → 接触判定」で固定し、**すれ違い（入れ替わり）も接触**とする。接触は隣接ではなく同一マス。

### ステップA3：回避可能性の保証と検証
1. **詰み防止の自動検証スクリプト**（`tools/` などリポジトリ外に置くか、PRに検証結果を貼る）：全15フロアで
   - 扉閉／開の両状態で、開始位置から階段・出口・ボス門・導きの灯・宝箱・採集点・NPC・サブイベント・スイッチへ到達できる
   - FOE の巡回経路上に「迂回路の無い1マス幅通路で出口を塞ぐ」区間が無い（巡回路上の各マスを除いても主要目的地へ到達できる）
   - FOE が階段・出口に隣接して停止し続けない
   - 挟み撃ち：2体のFOEが同じ1本道の両端から同時に迫る配置が無い
2. **FOE配置の見直し**：上記で問題が出た箇所の `path` を修正。各フロアに「FOEを観察できる安全な場所」があることを確認。
3. **戦闘への接続**：FOE戦の開始・逃走・撃破後の処理を整理（撃破状態の保存方式は Claude B と取り決める。既定はホーム帰還で復活＝現行維持、ただし「撃破→◯日（ホーム帰還◯回）で復活」に変えるならユーザーに提案）。世界樹の「戦闘中に近くのFOEが乱入」は**提案のみ**（実装はユーザー承認後、Claude C と調整）。

## 3. 触ってよいファイル／触らないファイル
| 可 | 内容 |
|---|---|
| `field.js` | 定数（視界半径以外）、通行判定、移動処理、`[PUZZLE]` 節、FOE 節（`fieldSpawnFoes`〜`fieldResetFoesAfterBattle`、`fieldTriggerFoeBattle`） |
| `data/field-maps.js` | 各フロアの `map` 文字列、`foes`、`objects`、`FIELD_PUZZLES`（**ファイル末尾の `FIELD_ENEMIES` は Claude C の担当。触らない**） |
| `data/story.js` | 扉・隠し通路のヒント用シーン追加のみ |
| `index.html` | 自分が変更したファイルの `?v=` のみ |

| 不可 | 理由 |
|---|---|
| `field.js` の宝箱・採集・`fieldSerialize`／`fieldDeserialize` | Claude B 担当 |
| `css/*`、地図の描画（`fieldDrawMap` の色・記号）、HUD のDOM構成 | GPT 担当。必要な表示はデータ提供で依頼 |
| `FIELD_VISION` の値、`saveVersion` | 視界は変更禁止。セーブ形式変更は B が一元管理 |
| `battle-ext.js`、`script.js`（`[FIELD]` フック1行以外） | Claude C／本体 |

## 4. セーブとの関係
- セーブに新しい項目が必要な場合は**自分で `fieldSerialize` を変えず**、Claude B に「キー名・型・既定値・旧セーブ時の扱い」を依頼する。
- 即時に必要なものは、既存の `fieldState.flags`（`true` のみ保存される）で表現できる範囲にとどめる（例：`door:<id>:open`、`hidden:<id>:found`）。既存の `puzzle:<ID>` フラグ名は変えない。

## 5. GPT に渡す表示用データ（PR本文にも記載すること）
| データ | 型 | 更新タイミング | 未発見時 |
|---|---|---|---|
| `fieldState.foes[i].mode` | `"patrol"｜"chase"｜"search"｜"return"` | FOE 移動ごと | 視界外かつ未踏マスのFOEは描かない（現行 `is-unexplored` 準拠） |
| `fieldState.foes[i].dir` | `"up"｜"down"｜"left"｜"right"` | 同上 | 同上 |
| `fieldState.foes[i].type` | `"patrol"｜"stationary"｜"chaser"｜"wanderer"` | 生成時 | 同上 |
| `fieldState.foes[i].nextTile` | `{tx,ty}｜null`（次の1歩の予定） | 同上 | 視界内のみ表示を推奨 |
| 扉オブジェクトの `state` | `"closed"｜"open"｜"locked"` ＋ `oneWay` | 開閉時 | 隠し扉は発見前は**オブジェクト自体を一覧から除外** |
| イベント | `field:foe:notice`（既存）、`field:foe:lost`、`field:door:open`、`field:hidden:found` | 発生時 | 未発見のものは発火しない |
