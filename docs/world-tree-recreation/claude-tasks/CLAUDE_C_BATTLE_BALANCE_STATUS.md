## 最上位指示
**『世界樹の迷宮』の「準備と判断が勝敗を分ける戦闘」を再現すること。**
弱点・耐性、状態異常・封じ、行動順、敵の予兆を読むことで有利になり、階層ボスは固有の攻略法を持つ「節目」として格が保たれる。

## 2. 実装ステップ（3項目ずつ。各ステップ終了時に報告）

### ステップC1：棚卸しと難易度曲線の設計（数値変更前に報告）
1. **計測**：既存の自動戦闘の検証方法（`LABYRINTH_SPEC.md` §5、`AI_HANDOFF.md` §8 の乱数固定）を使い、各階層の想定レベル・店売り装備・5人編成（未統合 #33 の有無の両方）で、雑魚1F／雑魚3F／FOE／ボスの「勝率・ターン数・HP減少率」を表にする。
2. **役割の定義**を数値目標として決める（例）：
   - 通常敵：1戦2〜4ターン。階層3Fでも単体でボスの数値を超えない。危険度は**組み合わせ・状態異常・属性**で上げる
   - 階層終盤の強敵：状態異常持ち・連携持ちで、放置すると崩れる
   - FOE：その階層到着時点では「避けるのが正解」。1〜2階層後に勝てる
   - 階層ボス：想定レベルで「対策すれば勝てる・対策しないと負ける」。HP・攻撃の単純増よりも、予兆→大技、フェーズ、弱点を突く機会で格を出す
3. 設計表と変更予定値を**ユーザーに提示して承認を得る**（ボスの数値・報酬は既存バランスへの影響が大きい）。

### ステップC2：状態異常・封じ・耐性の仕組み
1. **新しい状態の追加**（`data/status-effects.js` に定義、処理は `battle-ext.js`）：
   - `sleep`（睡眠：行動不能、被ダメージで解除、被ダメージ増）
   - `confusion`（混乱：一定確率で行動が乱れる）
   - `bindHead`（頭封じ：SPスキル・魔法系が使えない）、`bindArm`（腕封じ：物理スキル・通常攻撃威力低下）、`bindLeg`（脚封じ：回避0・逃走不可・速度低下）
   - 盲目等は必要性を判断して提案。既存IDは変更しない。
2. **敵の耐性**：敵データに `ailmentResist: { poison: 0.5, sleep: 0, bindHead: 1.0, ... }`（1.0＝通常、0＝無効）を追加。未定義は1.0。ボスは行動不能系に強い耐性＋**付与されるたびに耐性が上がる**（連続ハメ防止）。
3. **理不尽な行動不能ループの防止と対策手段**：
   - 味方側：同じ行動不能（麻痺・睡眠）は解除後1ターンの免疫、全員行動不能の連続は上限を設ける
   - 解除手段：治癒士の解除スキル（リフレッシュ等）の対象・SPコストを見直し、封じ解除を加える。解除アイテム（新規ID）は提案してから追加
   - 付与率は「基本付与率 × 敵耐性 × （LUC 等の既存補正）」の1本の式にまとめる。**#51・#52 が未統合なら、同じ式を二重に入れない**ように差し込み点を関数1つにして PR に明記する

### ステップC3：敵・ボスの数値と固有行動
1. **通常敵・終盤敵の調整**：`FIELD_ENEMIES` の能力値・行動（`ai[]`）・弱点耐性を、階層ごとに種族差が出るよう再配分。階層終盤には封じ・睡眠・混乱を使う敵、属性攻撃の敵を配置（**出現テーブル `floors[].encounter` は Claude A と被らないよう、変更するなら事前連絡**）。
2. **ボスの固有行動と予兆**：各階層ボスに「予兆 → 大技」の行動を最低1つ。予兆は戦闘ログ＋`battleEmit("boss:omen", {...})` で通知し、GPT が表示できるようにする。防御・回復・封じ・ブレイクで対処できる余地を残す。既存のドラゴン覚醒・魔王フェーズ・15ターン判定・BGM・報酬処理を壊さない。
3. **FOE の戦闘調整**：FOE は「到着時は避ける強敵」に。撃破報酬（固有素材）は GPT #56 と重複しないよう確認し、無ければ提案。

## 3. 触ってよいファイル／触らないファイル
| 可 | 内容 |
|---|---|
| `battle-ext.js` | 状態異常・耐性・付与式・ボスフェーズ処理 |
| `data/status-effects.js`、`data/boss-phases.js`、`data/enemies.js`、`data/enemy-variants.js`、`data/battle-rules.js` | 数値・定義 |
| `data/field-maps.js` 末尾の `FIELD_ENEMIES` ブロックのみ | 雑魚・FOE の能力値と行動（`map`・`foes`・`chests` は触らない） |
| `data/jobs.js`／`data/skill-trees.js` | 解除スキル・封じスキルの数値（職業変更 #37・#42 と衝突しないか確認） |
| `script.js` | `[EXT]` の1行フック追加と、ドラゴン等ボス行動の最小限の修正のみ |
| `index.html` | 自分が変更したファイルの `?v=` のみ |

| 不可 | 理由 |
|---|---|
| `field.js`、迷宮マップ | Claude A／B 担当 |
| `css/*`、戦闘画面のレイアウト・演出 | GPT 担当。状態アイコン等は `data/status-effects.js` の `label`・`icon` で提供 |
| `saveVersion`・セーブ構造 | Claude B が一元管理（戦闘中断データに新状態が入る場合は B に依頼） |
| 既存の状態異常ID・固定ID | 互換性 |

## 4. GPT に渡す表示用データ（PR本文にも記載すること）
| データ | 型 | 更新タイミング | 備考 |
|---|---|---|---|
| `EXT_STATUS_DEFS` の新ID | `{ label, icon, harm, kind: "ailment"｜"bind"｜"buff"｜"debuff" }` | 定義 | `kind` を追加して封じを区別 |
| 敵の `ailmentResist` | `{ [statusId]: number }` | 戦闘開始時 | アナライズ表示は**図鑑で判明済みの分だけ** |
| `battle:boss:omen` | `{ enemyName, actionName, turnsUntil, counter: "guard"｜"bind"｜"heal"｜"break" }` | 予兆発生時 | 演出は GPT |
| `battle:status:resist` | `{ targetName, type, reason: "immune"｜"resisted"｜"tolerance" }` | 付与失敗時 | 「効かない」表示用 |

- 既存のドラゴン／魔王の変身・撃破・報酬・BGM・15ターン判定を壊さない。
