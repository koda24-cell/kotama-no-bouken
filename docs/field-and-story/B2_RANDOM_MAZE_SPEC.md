# 第2階層 5F・6F ランダム迷宮 仕様（Claude 案 2026-11-16）

ユーザー決定事項
- 対象: 第2階層「凍てつく水源」の 5F（floors[1]）と 6F（floors[2]）。4F（floors[0]）は固定のまま
- 再生成: 探索に出るたび（ホームから出発／ボス撃破後の再出発）。迷宮内にいる間・セーブ＆ロードでは同じ形
- 仕掛けとNPC: 固定の部屋（テンプレート）として組み込み、位置はランダム

## 1. 方式
- 新規 `field/field-random-maze.js`（データ読み込み後、field.js の fieldArea より前に読み込む）
- `FIELD_RANDOM_FLOORS = { "2-1": {...}, "2-2": {...} }` に生成ルールを持つ
- シード = hash("kotama-b2", floorKey, fieldState.expedition)。乱数は mulberry32 等の決定的PRNG。Math.random は使わない
- `fieldArea()` の入口でランダム対象なら、生成済みの floor 定義（map / chests / gathers / foes / encounter）を返す。キャッシュキーにシードを含める
- マップサイズは既存の 5F・6F と同じ幅・高さ（外周は壁）

## 2. 固定エリア
- 5F: 上り階段 `<` 付近（約7×7）と下り階段 `>` 付近（約5×5）を既存マップから切り出したテンプレートで固定。位置は既存と同じ
- 6F: 上り階段付近と、ボス前（`S` 導きの灯・門・`B` ボスゲートを含む区画）を既存マップのまま固定

## 3. 固定部屋（位置ランダム）
- 5F「東西の合図石」: 門 h ＋宝箱 i の小部屋（門の内側に宝箱）、立て札 g は小部屋の前の壁。西の合図石 e はマップ西半分、東の合図石 f は東半分の部屋の壁（onWall）
- 6F: 行商人 a と見張り番 b の部屋（安全地帯 `_` を含む）、看板 `?`
- 1F・2F の木箱サブイベント c/d は現行どおり（5F に d がある場合は通常部屋に配置）

## 4. 生成アルゴリズム（部屋と通路）
1. 固定エリアと固定部屋を先に置く
2. 残りの領域に部屋（3×3〜7×5）を重ならないよう配置（部屋同士は壁1マス以上空ける）
3. 部屋の中心を最小全域木で結び、追加で15%程度ループ通路（行き止まりばかりにしない）
4. 通路幅は1マス。曲がりはL字
5. 行き止まりを2〜4個残す（滝・宝箱・採取の置き場）
6. 水 `~`: 部屋の一部に2マス以上の塊で置く。通路を水で分断しない（橋の代わり）。水に面した床は「岸」
7. 草むら `*`: 第2階層では使わない（既存に合わせる）

## 5. 置き物のルール
- 宝箱 `T`: 行き止まりか部屋の隅。数は既存と同じ（chests 配列の順）。**ユーザー決定: 探索ごとに復活する**。キーは `chest:2-f:e<expedition>:x:y` のように探索回数を含め、毎回開けられる。中身は既存 chests と同等の小報酬（初回の特別報酬が既存にあれば、それは1回きりのフラグで別管理）。5F 門の中の宝箱 i（a2-cache）は既存どおり1回きり
- 採取 `G`: 水辺の部屋か行き止まり、2〜3個
- FOE: 長めの通路か大部屋に巡回路（2〜4点）。スタート固定エリアから8マス以内には置かない。ボス前固定エリアには入れない
- 導きの灯 `S`: 6F ボス前のみ（固定）。5F は既存どおりなら1個を中間の部屋に

## 6. 必ず守る条件（生成後に検証し、失敗したら次のシードで最大50回やり直す）
- スタート→下り階段（5F）／スタート→ボスゲート（6F）へ、扉を開けずに歩いて行ける（6F の門が条件付きなら門の手前まで）
- 5F の宝箱 i は門 h の内側からしか取れない。合図石 e・f は通路から調べられる壁にある
- 宝箱・採取・NPC・看板・合図石すべてに隣接する床があり、到達可能
- FOE の巡回点はすべて到達可能な床で、互いにつながる
- 孤立した床がない。外周はすべて壁

## 7. セーブとの両立
- 保存済みの `expedition` からシードが決まるので、ロードで同じ迷宮が再現される
- **ユーザー決定: 踏破マップはランダム階では探索ごとに毎回埋め直し**。`explored["2-1"]`・`explored["2-2"]` を出発時（expedition が変わったとき）に消去する。磁軸の踏破率表示も新しい迷宮基準
- 位置 x,y はそのまま保存される（同じ形なので有効）。万一壁の中なら開始位置へ戻す

## 8. 3D（field-3d-b2-water.js）のルール
- 生成時に各マスへ役割を付け、`a.tileRoles` として渡す: room / corridor / deadend / shore / water / fixed / shrine-candidate
- 滝: 行き止まりの奥の壁（deadend）
- 柱V3: 部屋の角の壁際（room の角）、通路には置かない
- 凍った祭壇: 行き止まりまたは部屋の壁の祠候補（shrine-candidate、裏が壁で3方向が壁のマス）に各階1個
- 石造遺跡V4: 大部屋のふち・行き止まり手前
- 氷岸V11: 水 `~` の塊の縁
- 通り道（床マス）の中には装飾を置かない。固定エリアは既存の手置き配置を維持
- 同じシードなら3Dも完全に同じになる（装飾の乱数もシード由来）

### 8.1 実装どおりの配置規則（Claude 3Dフィールド担当 2026-11-16・v3：#203 の見た目の上に足す版）
`field/field-3d-b2-water.js` の `build()`。土台はユーザーが承認してマージした PR #203（明るいシアンの霧・鮮やかな青い岩・光る水脈の床・雪と光の粒・天井7m・結晶の溜まり場 `field/b2-crystals.js`・水道橋・氷の門・水車の中庭・祭壇のモニュメント・石柱・門柱）。
**露出・霧・照明・壁・床・天井・雪・光の粒・結晶・モニュメント・石柱の表現は一切変えない。** #203 の「マップの形から見せ場を探す処理」（滝＝行き止まりの奥の壁、吹き抜け＝3×3の広間、結晶の溜まり場＝行き止まり・部屋の角に最大3か所、橋＝浅瀬が3マス続く所、4マスが通れる角の柱、階段・灯の隣の門柱、壁の塊のモニュメント）は、ランダム階でもそのまま形から選ぶ。
`a.tileRoles` と `a.random` があるフロア（5F・6F）だけ、下の規則で GPT の素材を**足す**。4F（固定）は花の差し替え以外は #203 のまま（コードも乱数も同じ）。規則の番号はコード中のコメント（`規則A1` など）と対応する。

乱数と作り直し
- #203 の装飾は従来どおり `hash(x, y, k)`（マス座標）。足した素材は `H(x, y, k) = hash(x, y, k + salt)`、`salt = (a.random.seed mod 100003) + 1`。同じ buildKey なら同じ見た目
- 置く順番：滝 → 吹き抜け → 結晶の溜まり場 → モニュメント（6F、5F も合う壁の塊があれば）→ 祭壇の祠 → 部屋の角の石柱 → 石造遺跡 → 氷岸 → #203 の床・壁・天井の細部 → 花。足した大物のマス（propCells）では、#203 の壁ぎわの石筍・鍾乳石・根元の岩・4マスの角の柱だけ出さない（重なり防止。4F は propCells が常に空）
- モニュメントの壁の塊の探索は、合図石・立て札の付いた壁を含む塊を除く（ランダム階のみ）
- 足した GLB は1回だけ読み（同じファイルは `loadGltf` で共有）、作り直しのたびに複製して「区画×素材」でまとめる。読めない素材は置かないだけ
- 作り直し（buildKey が変わる・フロア移動）では `dispose()` がまとめた形・吹き抜け・しぶき・波紋など build 中に作った形と素材を捨てる（共有の素材 mats・キット・読み込んだ GLB の元の形は階層を離れるまで残す）。`themeInfo().ownedDisposed` で累計を確認できる

色味の調整（形は変えない。GLB の素材をそのまま使わず #203 の素材の仲間へ振り分ける）
- 茶色・灰色の石（遺跡の dark brown／sandstone gray、祭壇の limestone、氷岸の dark slate）→ 洞窟の岩のテクスチャと法線を持つ青い岩 `x:stoneDark`（0x5a8fbc）と霜色の石 `x:stoneMid`（0x8cbcd8）。砂ぼこり・欠けた石は #203 の淡い鉱物の石
- 透過（transmission）の氷 → #203 の結晶の氷 `crystalIce`／`crystalDeep`（重い透過描画を使わない）。雪 → 霜の白 `x:snow`
- 花 → 頂点色に元の素材の色を焼き込み、緑（葉・茎）を霜の青緑へ寄せる。花・花の氷・光る芯の3素材に、ほのかな発光（0x0e4c6a・0x1898d0・0x3cc4ff）

## 10. 実装メモ（Claude 迷宮システム担当 2026-11-16）

### ファイル
- `field/field-random-maze.js`（新規）：乱数・生成・検証・ゲーム接続。`index.html` で `field.js` の直前に読み込む
- 差し込み（すべて `[RANDOM-MAZE]` の目印付き・数行）：
  `field.js`（fieldArea：生成済みフロアを使う・キャッシュキーに迷宮タグ）、`field/field-navigation.js`（出発時の片付け・buildKey で再構築）、
  `field/field-render.js`（`fieldState.built = a.buildKey`）、`field/field-persistence.js`（expedition をマップより先に読む・旧セーブの踏破を捨てる・位置の確認）、
  `field/field-interactions.js`（採集点の定義 `o.gatherDef`・宝箱一覧のキャッシュを探索回数で作り直す）、`field/field-3d-view.js`（3Dの組み立てキーを buildKey に）
- テスト：`node tools/b2-random-maze/test.cjs [件数] [--ascii]`

### シード
- `seed = hash("kotama-b2|<フロア>|<expedition>|<試行>")`（cyrb53 系の32bit）→ mulberry32。試行は検証失敗ごとに +1、最大50回。50回失敗なら固定マップ
- 同じ expedition なら同じ形（ロードで再現）。`fieldArea(n,f).buildKey = "2-1@e<expedition>s<seed36進>"` が迷宮ごとに変わる

### 生成
- 5F（迷路）：奇数座標を格子とする。固定エリア（上り階段 x1–7,y17–19／下り階段 x19–23,y17–19）を既存から写す → 仕掛け小部屋（外の通路C→門h→A→宝箱i が一直線、A・i の他の辺は壁で固定、立て札g は C の横の壁）を向き・位置ランダムで置く → 小部屋2〜3個（3×3〜7×5、格子にそろえる、部屋の間は格子1マス以上） → Kruskal で全域木 → ループ6〜9本 → 行き止まりに宝箱・採取・木箱d を先に割り当て、空の行き止まりを2〜4個残し、残りは壁を抜いてつなぐ → 部屋の中に浅瀬 `*` の塊（2〜5マス） → 導きの灯S を中央に近い部屋の壁ぎわ → 西の合図石e（x<13）・東の合図石f（x>13）を「床が1方向だけに接する壁」に（部屋の壁を優先）
- 6F（洞窟）：固定エリア（開始 x1–4,y1–3 ※元の行商人aの位置は `_`／ボス前 x20–26,y14–16）→ 行商人a・見張り番bの部屋テンプレート（`#######`／`#a___b#`／`._____.`、下側が入口）を位置ランダム → 開き率56%の乱数＋セルオートマトン4回 → Dijkstra（壁を掘るのは高コスト＋ノイズ）で道 `,` をスタート→NPC部屋→ボス前、寄り道2本 → 孤立した広がりは大きければ道でつなぎ、小さければ埋める → 歩ける床が内側の46%未満ならやり直し → 草むら（浅瀬）`*` の塊6〜9個 → 宝箱（スタートから遠いくぼみ）・採取2・看板? をくぼみに
- FOE：既存と同じ数・同じ定義（enemy・sight）で path だけ作る。2点の往復。点と往復経路（fieldBfsStep と同じ探索）は、スタート固定エリアから8マスより遠く、他の固定エリアから2マスより遠い

### 仕様からの調整（既存コードに合わせた点）
- 水 `~` は使わず、浅瀬 `*` を水として使う：第2階層の既存マップに `~` は無く、`field-3d-b2-water.js` は `*` を水面（浅瀬）として描き、`~` は扱っていない。`*` は歩けるので通路を分断しない
- 採取 G の数：5F は既存どおり2、6F は既存0 → 仕様どおり2（フロアの gathers テーブル）
- 宝箱 T の数は各フロアの `chests` 配列の長さ（5F 2・6F 1）。中身は chests の順
- 固定エリアは 5F 上り 7×3・下り 5×3（迷路の格子で完結する範囲）

### 宝箱・採集点・踏破マップ
- 宝箱キー：`chest:<フロア>:e<expedition>:<x>:<y>`（探索ごとに復活）。出発時に前回までのランダム階の宝箱フラグを消す。門の奥の宝箱 i は `puzzle:a2-twin-stones:reward` のまま1回きり。木箱d・合図石・門は既存のIDのまま
- 採集点キー：`gather:<フロア>:g<番号>`（位置は毎回変わるが番号で数えるので「最初の採集から30分で戻る」ルールは探索をまたいで続く）。5F の g0/g1 は既存の `FIELD_GATHER_POINTS["2-1"]` の (1,1) take／(15,17) chop を引き継ぐ（`o.gatherDef`）
- 踏破マップ：出発時に `explored["2-1"]`・`explored["2-2"]` と、その階の発見済み（discovered）を消す。目印フラグ `rmaze:e<expedition>` を保存し、ロード時に目印が無ければ（旧セーブ）同じく消す
- 旧セーブの位置：壁の中、または開始位置から歩いて行けない場所（閉じた門の奥など）なら開始位置へ

### `a.tileRoles`（3D担当向け）
- `fieldArea(2,1)` / `fieldArea(2,2)` の戻り値に `tileRoles: string[h][w]`（`a.tileRoles[ty][tx]`）。固定マップのフロア・生成失敗時は `undefined`
- 値：
  - `wall`：壁（外周、壁に付いた物 e/f/g のマスも含む）
  - `shrine-candidate`：外周でない壁で、3方向が壁・1方向だけ床（祭壇の祠の候補）
  - `fixed`：固定エリア（既存の手置き装飾を維持する範囲）
  - `template`：仕掛け小部屋（5F：門h・A・宝箱i・立て札g と周囲の壁）／NPCの部屋（6F）
  - `room`：部屋（5F）／開けた洞窟（6F）
  - `corridor`：通路（5F の迷路）／6F の幅1マスのすき間
  - `road`：6F の道 `,`
  - `deadend`：三方が通れない床（物のマスも含む。滝・宝箱の置き場）
  - `water`：浅瀬 `*`
  - `shore`：`*` に接する床
- 優先順：fixed > template > (壁) > water > deadend > shore > room > road > corridor
