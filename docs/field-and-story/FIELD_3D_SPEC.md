### 1-2. 描画方式

| 項目 | 実装 |
|---|---|
| ライブラリ | three.js **r180**。`index.html` の importmap で jsDelivr から読む（`three` と `three/addons/`） |
| 読み込み方 | `field/field-3d-view.js` は **ES module**（`<script type="module">`）。他の field 系は classic script のまま |
| 既存コードとの接点 | 3か所のフック（`// [FIELD-3D]`）。① `fieldBuildDom()` の最後で `KotamaField3D.build()`、② `fieldRender()` の最後で `KotamaField3D.frame()`、③ `fieldUpdate()` の入力で、3D表示中は `KotamaField3D.input()` |
| 状態の扱い | `fieldState`・`fieldArea()`・`fieldTileAt`・`fieldLetterDef`・`fieldDoorOpen`・`fieldCharSolid` などを**読むだけ**。書き換えるのは入力時の向き（`fieldState.dir`）と `stepUntil` だけで、移動は既存の `fieldTryStep()` を通す |
| 描画のタイミング | 探索画面のループ（`requestAnimationFrame`）ごとに1回。上限は localStorage の `kotama.field3d.maxFps`（既定は上限なし） |
| マップの組み立て | フロアごとに、マスを見て GLB を複製して置く（ジオメトリと素材は共有）。置いた物は `matrixAutoUpdate=false` で行列を固定する |
| 1マス | 4m（`CELL = 4`）。マス (tx, ty) の中心は world (tx×4, 0, ty×4)。北（`up`）は −Z |
| 色の処理 | ACES Filmic トーンマップ、露出 1.3、sRGB 出力 |
| 画質（localStorage の `kotama.field3d.quality`） | `high`：解像度は最大2倍、点光源14、光のにじみ（UnrealBloom 強さ0.45）。`low`：解像度は最大1.25倍、点光源6、にじみなし。既定は PC が `high`、タッチ端末が `low` |

## 2. 共通部分と階層固有部分（2層以降で再利用するための整理）

### 2-1. いまのコードでの区分

| 区分 | 中身 | いまの場所 | 2層でそのまま使えるか |
|---|---|---|---|
| **共通（階層に依存しない）** | フック3か所、一人称の入力、カメラ、描画ループ、画質設定、点光源の使い回し、GLB の読み込みと複製、物の状態の反映（宝箱・採集・扉・仕掛け・イベント）、FOE の表示、目印、2D/3D 切り替え、フォールバック | `field/field-3d-view.js` | **使える** |

### 2-2. 2層を足すときの設計（未実装。実装はユーザー承認後）

1層の表示を変えずに2層を足すため、階層ごとの違いを「テーマ設定」にまとめる。

```text
field/field-3d-view.js         共通の処理（いまのファイル）
field/field-3d-themes.js       階層ごとのテーマ設定（新設予定・ES module）
  THEMES[1] = { base: 'assets/3d/dungeons/b1_ancient_forest/', files: {...いまの FILES...},
                fog: { color: 0x0c1a20, density: 0.042 }, background: 0x070d11,
                hemi: { sky: 0x7aa8c4, ground: 0x1c241c, high: 1.25, low: 1.7 },
                floorMix: {...}, wallMix: {...}, decor: {...}, npc: {...}, events: {...}, water: {...} }
  THEMES[2] = { base: 'assets/3d/dungeons/b2_<name>/', ... }
```

- 共通の処理は `THEMES[fieldState.area]` を読み、無い値は第1階層の値で補う。
- **第1階層の設定は、いまのコードの値をそのまま移す**（値は変えない）。移したあと、第1階層の見た目が同じことを、同じ位置・同じ向きのスクリーンショットの比較で確認する。
- `AREAS_3D` は「`THEMES` にある階層」に置き換える。
- 素材の読み込みのキャッシュは、いまは素材フォルダからの相対パスだけをキーにしている。**階層が増えると同じ名前のファイルがぶつかる**ので、フルパスをキーにする（§5 の課題1）。

## 3. 水面・滝・水流・水しぶき・反射を足せる構造か

### 3-1. 確認結果

| 表現 | いまの対応 | 理由（コード・ライブラリの確認） |
|---|---|---|
| GLB に入れたアニメーション（ボーン・形の変化・移動回転） | **未対応** | 読み込み時に `gltf.scene` だけを残し、`gltf.animations` を捨てている。AnimationMixer も無い。複製は `Object3D.clone(true)` なので、ボーン付きのモデルは正しく複製できない（`SkeletonUtils.clone` が必要） |
| テクスチャを流す（水面・水流・滝の UV スクロール） | **未対応** | 毎フレーム素材を更新する処理が無い。three r180 の GLTFLoader は `KHR_texture_transform`（静的なずらし）は読めるが、`KHR_animation_pointer`（素材の値を動かすアニメーション）は**読めない**ので、glTF だけでは表現できない |
| 水しぶき・霧・粒子 | **未対応** | 粒子の仕組みが無い |
| 映り込み | **未対応** | 環境マップも反射面も無い。three r180 の addons には `Reflector`・`Water`・`Water2` があるが使っていない。`Water`／`Water2` は法線や流れのテクスチャを別に必要とし、それはリポジトリに無い |
| 半透明の水 | **一部** | 素材の透明度は GLB のまま使えるが、並べる順の調整は無い |
| 毎フレームの更新の入口 | **ある** | `frame()` が毎フレーム呼ばれ、経過時間 `dt` もある。FOE の脈動と目印の回転はここで動かしている |
| 止まっている間の描画 | 常に描画 | 描画は探索ループごとなので、アニメーションを足しても描画の回数は増えない |

**まとめ**：毎フレームの更新の入口はあるので、そこに「アニメーションの再生」「UV を流す」「粒子」「反射」の4つを足せば対応できる。ただし、**いまはどれも実装されていない**。素材側（GPT）は §3-2 の約束で作れば、実装が後になっても作り直さずに済む。

### 3-2. 水とエフェクトの素材の約束（実装時にこの書式を読む）

素材の作り方の詳細は `FIELD_3D_ASSET_GUIDE.md` §6。ここでは実装側が読む書式だけを定める。

| 表現 | 素材側の書き方 | 実装側（Claude）がやること |
|---|---|---|
| ループするアニメーション（滝の水の帯、揺れる水草、回る水車など） | GLB に AnimationClip を入れる。名前は `loop`（常時）。複数あるときは `loop_<名前>` | 読み込み時に `animations` を残し、置いた物ごとに AnimationMixer で `loop*` を繰り返し再生する。ボーン付きは `SkeletonUtils.clone` で複製する |
| UV を流す（水面・水流・滝） | 流したい素材の glTF の `extras` に `{"b1":{"uvScroll":[u, v]}}`（1秒あたりの UV の移動量。例：滝 `[0, -0.6]`） | 素材ごとに `map`／`normalMap`／`emissiveMap` の `offset` を毎フレーム進める（同じ素材を共有する物はまとめて動く） |
| 水しぶき・霧・泡 | ノードの `extras.b1.emitters` に `[{ "type":"splash"|"mist"|"bubbles", "pos":[x,y,z], "size":m, "rate":個/秒, "color":"#rrggbb" }]` | 粒子の仕組み（Points とスプライト）を共通部分に作り、近いものだけ動かす |
| 反射する水面 | 水面のメッシュの素材名を `water_*` にし、`extras.b1.water = { "reflect": true }` | 高画質のときだけ反射面（`Reflector` か環境マップ）に置き換える。低画質は不透明の水のまま |
| 水の音（任意） | `extras.b1.sound = { "loop": "<assets/se/ 下の英数字のファイル名>" }` | 近づくと鳴らす（未実装・要相談） |

- `extras` は glTF の標準の項目なので、Blender で作る場合は「カスタムプロパティ」として書けば GLB に入る。
- 第1階層の素材が使っている `extras.b1.lights` と同じ `b1` の下に置く（名前は既存に合わせた。階層番号の意味ではない）。

## 4. 素材の追加方法・形式・命名・配置

詳細は `FIELD_3D_ASSET_GUIDE.md`。要点だけを書く。

| 項目 | 決まり（第1階層の実装に合わせたもの） |
|---|---|
| 形式 | glTF 2.0 Binary（`.glb`）。PBR（色・法線・ORM＝R:遮蔽/G:粗さ/B:金属）。テクスチャは埋め込み |
| 座標 | 単位はメートル、上は +Y、**素材の正面は +Z**。マップの北（`up`）は −Z（world 側の約束で、素材の正面とは別） |
| 原点 | 既定は底面の中央。壁部品は内側の面の下端中央、天井部品は下面、扉・格子は床面の中央。例外は manifest の説明に書く |
| 寸法 | 1マス4m、壁の高さ4m、壁の厚み0.8m（マスの境に置く板）、扉の開口は幅2m・高さ3m |
| 命名 | 半角の小文字スネークケース（例 `mod_wall_4m.glb`）。接頭辞：`mod_`（組み立て部品）、`gimmick_`（仕掛け）、`gather_`（採集）、`npc_`、`foe_`、ほかは内容を表す名前 |
| フォルダ | `assets/3d/dungeons/b<階層番号>_<英名>/`（例 `b1_ancient_forest`）。中は `modules/`（床・壁・天井・階段・仕掛け・採集）・`props/`（小物・NPC・飾り）・`fx/`（水・エフェクト。2層から新設）・`renders/`（確認画像）・`manifest.json`・`ASSET_LIST.md` |
| 光源 | 発光する場所は `extras.b1.lights = [{ pos:[x,y,z], color:0xRRGGBB, intensity, range }]` |
| 容量の目安 | 1点あたり 1MB 以下（大きな目印は 4MB 以下）。階層全体で 40MB 程度まで |
| 登録 | manifest に載せたうえで、`field-3d-view.js`（2層以降はテーマ設定）の素材一覧に追加する。**一覧に無い素材は表示されない** |

## 5. 2層を足しても1層が壊れないための約束

| 約束 | 内容 |
|---|---|
| 1層の値は変えない | テーマ設定への移し替えは「値をそのまま移す」だけ。色・割合・素材・カメラを変えない |
| 1層の素材は上書きしない | 2層の素材は別フォルダ（`b2_*`）に置く。共通で使いたい部品は**コピーせず**、テーマ設定から1層のパスを指す |
| 回帰の確認 | 2層の PR ごとに、次の3つで1層が同じに見えて同じに動くことを確かめる。① 1層の `tools/b1-3d/game-test.js` がエラー0件、② 1層の決まった位置・向きのスクリーンショットを変更前後で比べる（同じ乱数・同じ画質）、③ 既存テスト（world-tree 5種・battle-sim） |
| 範囲を広げない | 有効な階層は、テーマ設定がそろった階層だけ。素材が足りない階層は2D表示のまま |
| ゲームのルールは変えない | マップ・FOE・イベント・セーブは field 系のまま。3D側で新しい通行判定や状態を持たない |
| 読み込みの失敗 | 2層の素材を読めなくても、1層や2D表示に影響しないようにする（いまも素材の読み込みに失敗すると2D表示に戻る） |
| メモリ | 階層を移るときに前の階層の素材を手放す処理は**まだ無い**（キャッシュを捨てていない）。2層の実装で必ず足す（§6 の課題4） |
