# フィールド探索・ランダムエンカウント・ストーリー追加：作業分担

- 対象：kotama-no-bouken
- 基準ブランチ：`development`
- 作成：Claude（2026-11-06）
- 状態：**分担確定版（実装はこの文書のあとに着手）**
- 関連文書：同フォルダの `FIELD_SPEC.md`（共通インターフェース）、`CLAUDE_TASK.md`、`GPT_TASK.md`

これまで育ててきた戦闘フェーズに、**戦闘以外のフェーズ**を追加する。ユーザーからの依頼は次の4点。

1. アンダーテールのような**見下ろし型の自由移動**を追加する。
2. 移動中の**ランダムエンカウント**で戦闘に入る。
3. **ストーリー**を追加する。
4. 戦闘中の**敵アナライズ**を常時表示ではなく、画面端のボタンで開閉し、**敵・味方それぞれの状態**を確認できるようにする。

参考作品（アンダーテール）は「操作感・画面構成」の参考であり、画像・文章・音楽・キャラクターは一切流用しない。

---

## 1. 新しいゲームの流れ

```
ホーム ─START→ エリア選択（＝従来のステージ選択）
                 │
                 ▼
          フィールド（エリア1〜5）
           ├ 歩く → 一定歩数ごとにランダムエンカウント → 戦闘 → 勝利/逃走でフィールドへ戻る
           ├ NPC・看板を調べる → 会話ウィンドウ（ストーリー）
           ├ 導きの灯（セーブポイント）→ 全回復＋オートセーブ
           ├ 宝箱 → ゴールド/回復薬
           └ エリア最奥のボスゲート → ボス前会話 → 従来のステージ戦（スライム〜魔王）
                                                   │
                                     勝利 → 次のエリアのフィールドへ（5面はENDINGへ）
```

- 従来の5ステージ・隠しボス・チュートリアル戦闘はそのまま残す。**ボス戦＝従来のステージ戦**で、数値・行動・報酬は変えない。
- フィールドの雑魚戦は新しい敵データ（`data/field-maps.js`）を使い、ステージクリア・ランク・スキルポイントには影響しない（ゴールドと素材のみ）。

### 責任の境界
- **Claude**：動き・判定・データ・戦闘との接続・セーブ・イベント発火。見た目は「遊べる最低限の仮スタイル」まで。
- **GPT**：見た目・アニメーション・素材・文章の推敲。`field.js` の処理や `[FIELD]` フックは変更せず、必要なら `field:*` イベントを使う。足りない情報があれば Claude に追加を依頼する。
- 同じファイルを同時に編集しない。`css/06-field.css` は **Claude のPRがマージされた時点で GPT に引き継ぐ**（以降 Claude は触らない）。`data/story.js` は Claude PR マージ後、文章部分を GPT が推敲できる。

## 4. ユーザー確認が必要な点（仮決めで進める）

| 項目 | 仮決め | 理由 |
|---|---|---|
| ボス戦開始時のHP/SP | **全回復してから開始**（従来どおり） | ボス戦のバランスを変えないため |
| 雑魚戦のHP/SP | **持ち越し**。導きの灯で全回復 | 探索の緊張感（アンダーテール・RPGの定番） |
| 雑魚戦の敗北 | ホームへ戻る。所持品・ゴールドは失わない。次回はエリアの入口から | 既存の敗北処理に合わせる |
| 雑魚戦の撤退 | 確認ダイアログ→フィールドへ戻る（報酬なし） | 「にげる」相当 |
| エンカウント頻度 | 安全マス以外を 12〜26マス歩くごとに1回（エリアで変化） | 連戦にならない間隔 |
| フィールドBGM | `仕分け雨/` の未使用曲を仮割り当て | 権利確認と最終選曲はユーザー |

## 5. 共通の保護条件

- 既存のダメージ計算・命中・行動順・スキル効果・敵AI・ボスの数値を変えない。
- 既存のセーブデータを壊さない（新項目は無くても読める）。既存の固定ID（イベント・実績・ステージ）を変えない。
- 既存素材を削除・上書きしない。新素材は半角英数字のファイル名で `ASSETS_CREDITS.md` に記録。
- 外部ライブラリ・CDNは導入しない。
- `main` への反映はユーザーの承認後。
