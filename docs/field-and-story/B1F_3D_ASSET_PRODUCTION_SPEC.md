# B1F「はじまりの樹海」3D素材制作仕様

- 対象：kotama-no-bouken / B1F
- 作業担当：GPT（3D表示基盤・素材仕様）
- 品質方針：高品質優先。ただしiPhoneで探索を継続できる性能を確保する
- 基本形式：GLB（glTF 2.0）
- 状態：初回6モデルを制作・manifest登録済み。最終品質化（テクスチャ・LOD・実機検品）は継続

## 1. アートディレクション

「長い年月をかけて古代遺跡を森が飲み込んだ地下樹海」。
- 主素材：風化した古代石、湿った土、苔、太い樹根、古代金属。
- 色：深い森林緑、青緑、湿った灰色、古い青銅。発光部のみ青白〜淡い翡翠色。
- 印象：美しいが、奥へ進むほど不穏。ホラー一辺倒にはせず、冒険の期待感を残す。
- 避ける表現：均一な緑一色、過剰な蛍光色、壁面を埋め尽くす細かい装飾、視界を塞ぐ大量の粒子。
- シルエット：通路の先に大樹の根・崩れた柱・古代装置など、遠くから識別できるランドマークを置く。

## 2. ワールド寸法・座標

現行3D Adapterの基準に合わせる。

| 項目 | 基準値 |
|---|---:|
| 1マス | 4 world units |
| 通路幅 | 4 units（1マス） |
| 壁高さ | 4 units |
| プレイヤー視点高さ | 1.68 units |
| 標準扉 | 幅3.2 / 高さ3.6 units |
| 小物の設置高さ | 床から0〜1.5 units |

- モデル原点は原則として床接地点の中央。
- 前方はモデルのローカル -Z を基準とする。
- GLBの単位はメートル相当として制作し、出力時にスケールを適用してから書き出す。
- モデルは既存マップの通行幅・扉セルを侵食しない。装飾のコリジョンは表示側で新設しない。

### D. FOE表示（後工程）

FOEモデルはゲーム側の敵定義・sprite・状態と対応させる。初期段階で敵AIや当たり判定をモデルへ持たせない。まずはシルエットと表示同期を優先し、アニメーションは既存状態の読み取り後に追加する。

## 4. テクスチャ仕様

- PBR：Base Color / Normal / ORM（Occlusion, Roughness, Metallic packed）を基本とする。
- 色空間：Base ColorはsRGB、Normal/ORMはNon-Color。
- 解像度目安：大型ランドマーク2048pxを上限目安、壁・床の共有アトラス2048pxを基本、必要性が明確な場合のみ4096px、小物512〜1024px。
- 可能な限り素材アトラスを共有し、同じ石・苔の素材を使い回す。
- 高周波ノイズや微細な凹凸を過剰に入れない。スマホ画面で潰れない大きな面変化を優先。
- 透過テクスチャは葉・発光面など必要な箇所だけに限定。

## 5. ポリゴン・LOD・描画負荷

品質優先だが、マップ全体を高密度モデルで埋めない。
- 壁・床は原則として共有Geometry/InstancedMeshまたは結合メッシュ。
- 小物は同一素材・同一Geometryを共有する。
- LOD0は近景用の高品質モデル、LOD1は中距離用で小さな凹凸・内部パーツを削減、LOD2は遠景用でシルエットと大きな色面だけを残す。
- LOD距離は固定値で決め打ちせず、カメラ距離と実機負荷で調整。
- 画面外の装飾はFrustum Culling対象とする。
- 小型の発光植物を一つずつPointLightにしない。Emissive表現を基本にし、局所ライト数は限定。
- 影は重要な大物に限定し、全小物にリアルタイム影を付けない。
- パーティクルは少数のPoints/InstancedMeshを基本とし、粒子ごとのMesh生成を避ける。

## 6. GLB納品ルール

- 推奨納品形式：GLB / glTF 2.0。初回6モデルはGitHub上での差分管理と検品を容易にするため、バッファをdata URIへ埋め込んだ `.gltf` 形式で仮納品。最終版では必要に応じてGLBへ変換する。
- ファイル名：上記IDを小文字ケバブケースに変換（例：env-stone-wall-a.glb）。
- 原点・向き・スケールを仕様に合わせる。
- 不要なカメラ・ライト・空オブジェクトを削除。
- マテリアル名を用途が分かる名前にする。
- テクスチャをGLBへ同梱する。
- 可能ならDraco/Meshopt等の圧縮を検討するが、読み込み環境との互換性を確認してから採用。
- 1素材1ファイルを基本とし、複数バリエーションは同一ファイル内の別ノードまたは別ファイルで明示する。
- 既存アセットの改変・流用時は出典・ライセンスを記録する。

## 7. 推奨フォルダ構成

```text
assets/
  field-3d/
    b1/
      environment/
      ruins/
      nature/
      props/
      foes/
      manifest.json
```

manifestは素材ID・相対パス・スケール・配置補正・LOD情報を保持する。ゲームロジックや既存のassets/music・assets/seには影響させない。

## 9. 実装上の注意

初回制作モデルは追加済みだが、完成扱いにはしない。現時点の6モデルは形状・色面による第1制作版であり、PBRテクスチャ、UV、LOD、アニメーション、実機表示の検品が残る。未制作素材は仮表示を維持し、素材不足を完成扱いしない。

本編統合時は必ず既存のfieldArea()・移動関数・操作関数・FOE状態を正とする。3D素材は表示専用とし、扉の開閉・宝箱報酬・採集回数・イベント進行・セーブ処理をGLB側へ実装しない。

## 10. 初期アセット予算（制作時の目安）

以下はB1Fの初回納品で使う**上限目標**。見た目に必要な箇所へポリゴンを集中し、同じ素材を多数配置する前提で管理する。数値は実機計測後に改定する。

| 素材 | LOD0目標 | LOD1目標 | LOD2目標 | 補足 |
|---|---:|---:|---:|---|
| 石壁セグメント | 2,500 tris以下 | 1,200以下 | 350以下 | 共有・インスタンス配置前提 |
| 石床/土床 | 1,200以下 | 500以下 | 150以下 | タイル境界の段差を作らない |
| 太い根/壁根 | 3,500以下 | 1,500以下 | 400以下 | 曲線の外形を優先 |
| 崩れた石柱 | 8,000以下 | 3,500以下 | 900以下 | 破断面は近景のみ細かく |
| 古代アーチ | 12,000以下 | 5,000以下 | 1,200以下 | 遠景では輪郭を維持 |
| 宝箱/採集/灯り | 4,000以下 | 1,600以下 | 450以下 | 開閉差分は共有部品を使う |
| シダ/苔/菌類 | 1,500以下 | 600以下 | 180以下 | 透過面・両面描画を抑制 |

### テクスチャ・ファイル予算

- 壁・床の共有アトラス：2048pxを基本。Base Color / Normal / ORMを同じUV配置でまとめる。
- 大型ランドマーク：2048pxを基本、4096pxは近景で必要性が確認できた素材だけ。
- 小物・植物：512〜1024pxを基本。色違いは可能ならマテリアルパラメータで表現。
- 1素材GLBの目標サイズ：環境基礎は2MB以下、ランドマークは4MB以下、小物は1MB以下を目安とする。圧縮後のサイズで検収する。
- LOD1はLOD0から概ね50%以下、LOD2は概ね20%以下の三角形数を目安にする。シルエットを壊す場合は削減率より視認性を優先する。
- 透過マテリアルは必要最小限。葉のカード表現は重なりすぎないようにし、可能ならアルファテスト相当の表現を検討する。
- 同じ素材の色違い・配置違いでGLBを大量複製せず、共有Geometry/MaterialまたはInstancedMesh化できる構造にする。

### 納品時に必須の確認情報

- assetKey、ファイル名、カテゴリ、原点、寸法、適用スケール。
- LODの有無と切替用ノード名（LOD0 / LOD1 / LOD2）。
- Mesh数、Material数、Texture数、三角形数、GLBファイルサイズ。
- テクスチャ解像度とBase Color/Normal/ORMの有無。
- 制作者、出典、ライセンス、改変・再配布条件。
- ゲーム画面での近景・中景・遠景スクリーンショット。

### manifestキーの接続ルール

manifestのキー名は、配置レイヤーが参照するassetKeyと一致させる。現行manifestの `mossClusterA` / `fernA` / `glowPlantA` / `fungusA` などは制作管理用の識別子であり、実際の本編接続時には `assetKeys` の明示マッピングを設定する。キーの不一致で仮形状へ戻る状態を検品時に見落とさないこと。
