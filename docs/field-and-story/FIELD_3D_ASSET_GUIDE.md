# 3D迷宮の素材制作ルール（GPT 向け）

- 読む人：3D素材・背景・エフェクトを作る GPT。統合・配置・実装は Claude、確認と最終承認はユーザー。
- 位置づけ：development で動いている一人称3D表示（`field/field-3d-view.js`）と、第1階層の素材（`assets/3d/dungeons/b1_ancient_forest/`）に合わせた決まり。システム全体の仕様は `docs/field-and-story/FIELD_3D_SPEC.md`。
- **ここに無い寸法・約束を、推測で決めない。** 迷ったら、作る前に Claude かユーザーに確認する。
- GPT の未統合ブランチにある `B1F_3D_ASSET_PRODUCTION_SPEC.md`（目の高さ1.68、ケバブケースの名前、4×4×4の壁）とは約束が違う。**development の約束（このファイル）を正とする。**

---

## 1. 形式

| 項目 | 決まり |
|---|---|
| ファイル | glTF 2.0 Binary（`.glb`）。1素材＝1ファイル |
| 素材 | PBR の Metallic-Roughness。色（sRGB）・法線（OpenGL 方式、+Y）・ORM（R:遮蔽、G:粗さ、B:金属を1枚に）。発光は emissive（色＋強さ。`KHR_materials_emissive_strength` は使ってよい） |
| テクスチャ | GLB に埋め込む。JPEG（色・ORM・法線）を基本にする。透明が必要なものだけ PNG。一辺は 256／512／1024px（大きな目印だけ 1024） |
| 使ってよい拡張 | `KHR_texture_transform`（静的なずらし・繰り返し）、`KHR_materials_emissive_strength`、`KHR_mesh_quantization` |
| 使わない拡張 | `KHR_draco_mesh_compression`・`KHR_texture_basisu`（読むための追加ファイルが無い）、`KHR_animation_pointer`（three r180 では読めない）、`KHR_lights_punctual`（光は §5 の書き方で） |
| 頂点 | 位置・法線・UV（TEXCOORD_0）を必ず入れる。頂点カラーは使わない |
| 容量 | 1点 1MB 以下が目安。大きな目印（巨木など）は 4MB 以下。階層全体で約40MB まで |

## 2. 座標・寸法・原点

| 項目 | 決まり |
|---|---|
| 単位 | 1 = 1m |
| 上 | +Y |
| 素材の正面 | **+Z**（プレイヤーが見る側。Blender で作るときは正面を −Y に向けて書き出すと glTF で +Z になる） |
| 1マス | 4m×4m。壁の高さ 4m、天井の下面は y=4 |
| 目の高さ | 1.6m（カメラはマスの中心から 1.1m 後ろ。正面のマスの物は約5m先に見える） |
| 原点 | 既定は**底面の中央**（床に置いたときの接地点）。例外は下の表 |

| 種類 | 原点と向き |
|---|---|
| 壁部品 | 内側の面の下端中央。内側（通路側）が +Z。厚みは z = −0.8〜0（マスの境に置く板） |
| 床部品 | 上面 y=0、中心。4×4m で、隣のマスと継ぎ目なく並ぶこと（縁の高さを0にそろえる） |
| 天井部品 | 下面 y=0、中心（ゲームは y=4 に置く）。上（+Y）に厚みを持たせる |
| 扉・格子・開口に入れる物 | 床面の中央。扉の面は z=0。開口は幅2m・高さ3m |
| 垂れ下がる物（蔓・繭・水滴の筋など） | 上端（取り付け位置） |
| 壁に重ねる物（結晶脈・爪痕・滝の帯など） | 壁面の下端中央。+Z へ突き出す |

## 3. 命名とフォルダ

- ファイル名：半角の小文字スネークケース。内容が分かる英語（例 `waterfall_wall_4m.glb`、`water_surface_4m.glb`）。
- 接頭辞

| 接頭辞 | 用途 |
|---|---|
| `mod_` | 組み立て部品（床・壁・天井・階段・段差）。寸法があるものは末尾に `_4m` |
| `gimmick_` | 仕掛け（扉・レバー・踏み板・合図石など） |
| `gather_` | 採集ポイント（`gather_herb_point` など） |
| `npc_` | NPC（`npc_merchant` など。ゲームの NPC の `id` に合わせる） |
| `foe_` | FOE の気配・FOE 本体 |
| `fx_` | 水・エフェクト（`fx_splash`、`fx_mist` など。2層から） |
| なし | 小物・飾り（`fern_cluster` など） |

- 開閉など見た目が切り替わる物は、別ファイルの差分にする（例 `sealed_treasure_chest` と `sealed_treasure_chest_open`）。寸法と原点は同じにする。
- フォルダ：`assets/3d/dungeons/b<階層番号>_<英名>/`

```text
assets/3d/dungeons/b2_<英名>/
  modules/   床・壁・天井・階段・段差・仕掛け・採集
  props/     小物・飾り・NPC
  fx/        水面・滝・水流・水しぶき・霧など（動くもの）
  renders/   確認画像（実際の GLB を描画したもの）
  manifest.json   素材一覧（§7）
  ASSET_LIST.md   素材一覧（人が読む表）
```

- 既存のフォルダ（`b1_ancient_forest`）のファイルを、上書き・改名・削除しない。1層の部品を2層でも使うときは、コピーせず Claude に「1層のこれを使う」と伝える。

## 4. 作る物の一覧（階層ごと）

ゲームに出てくる物と3D素材の対応（`FIELD_3D_SPEC.md` §1-7）に合わせて作る。1層と同じ役割の物は、同じ接頭辞・同じ寸法にする。

| 必須 | 種類 |
|---|---|
| 必須 | 床2〜3種、壁2〜3種（崩れた壁を1つ含む）、天井1〜2種、上り階段、下り階段 |
| 必須 | 宝箱（閉じた・開いた）、採集3種（採取・伐採・採掘）、導きの灯、看板（立てる物・壁に付ける物） |
| 必須 | その階層の仕掛け（扉・スイッチ。種類は `data/field-maps.js` の objects を見る）、サブイベントの物（`sprite` ごと）、NPC（`id` ごと） |
| 推奨 | 目印になる大きな物、壁際の飾り、光る物（暗所で進む方向を示す） |

## 5. 光源の書き方

光を出す物（灯火・発光植物・光る水など）は、GLB のルートノードの extras に光源を書く。ゲームは近いものから点光源を割り当てる。

```json
{ "b1": { "lights": [ { "pos": [0, 1.2, 0], "color": 8382207, "intensity": 1.2, "range": 4 } ] } }
```

- `pos` は素材の原点からの位置（m）、`color` は 0xRRGGBB を10進で書いた値、`range` は届く距離（m）。
- 1素材に3つまで。光は「暗所で形と進む方向が分かる」ために使う。
- 名前の `b1` は既存の書式に合わせたもので、第1階層という意味ではない（2層の素材でも `b1` と書く）。

## 6. 水・滝・水流・水しぶき・反射（2層の水源エリア向け）

**いまのゲームは、ここに書く動きを再生できない。**（`FIELD_3D_SPEC.md` §3）
この書式で作っておけば、Claude が再生の仕組みを足したときに作り直さずに済む。

| 表現 | 作り方 |
|---|---|
| ループするアニメーション（滝の帯の揺れ、水草、水車など） | GLB に AnimationClip を入れる。名前は `loop`（複数なら `loop_<名前>`）。最初と最後がつながること。ボーンを使ってよい |
| 流れる水面・水流・滝 | 流したい素材の extras に `{"b1":{"uvScroll":[u, v]}}`（1秒あたりの UV 移動量）。テクスチャは継ぎ目なく繰り返せるものにする。流れる向きは UV の +v/−v に合わせる |
| 水しぶき・霧・泡 | 粒子そのものは作らなくてよい。発生させる位置をノードの extras に `{"b1":{"emitters":[{"type":"splash","pos":[x,y,z],"size":1.0,"rate":20,"color":"#bfefff"}]}}` と書く（`type` は `splash`／`mist`／`bubbles`） |
| 反射する水面 | 水面だけを別メッシュにして、素材名を `water_` で始め、extras に `{"b1":{"water":{"reflect":true}}}`。水面の下（水底）も作っておく（反射を使わない低画質ではそのまま見える） |
| 半透明 | 水面の不透明度は 0.6 以上を目安にする（重なり順の調整が無いため） |
| 滝の寸法 | 壁に重ねる物として作る（壁面の下端中央が原点、幅4m・高さ4m以内）。高さが4mを超える滝は、上下に分けた部品にする |
| 水のマス（`~`） | 4×4m の水面の部品（`fx_water_surface_4m` など）と、岸の縁（通れるマスとの境）の部品を分けて作る |

- 動きの速さ・色は素材ごとに決めてよい。ただし、暗所で進む方向が分かる見た目を優先する。
- 水の音を付けたい場合は extras に `{"b1":{"sound":{"loop":"<ファイル名>"}}}` を書けるが、再生は未実装。音のファイルは `assets/se/` に半角英数字の名前で別途置く。

## 7. manifest と一覧

- `manifest.json` は第1階層と同じ形式にする（`tools/b1-3d/manifest.js` が作る形）。最低限、次の項目を入れる。
  - 素材ごと：`id`、`file`（フォルダからの相対パス）、`category`、`name_ja`、`desc_ja`（原点・向きの例外もここに書く）、`bytes`、`tris`、`sizeMeters`、`materials`、`pointLights`、`animations`（クリップ名の一覧。無ければ空）、`emitters`（数）
  - 全体：`count`、`totalBytes`、`conventions`（単位・上・正面・原点）
- `ASSET_LIST.md`：ファイル・名前・分類・寸法・三角形数・容量・説明の表。

## 8. 納品前の確認（GPT が行う）

- [ ] GLB が glTF 2.0 として読み込める（three.js の GLTFLoader か Blender で開いて確認）
- [ ] 単位・上・正面・原点が §2 のとおり
- [ ] 床・壁を2つ並べて、継ぎ目と高さがそろう
- [ ] テクスチャが埋め込まれ、容量が §1 の目安以内
- [ ] 光源・アニメーション・UV の流れ・発生位置を §5〜§6 の書式で書いた
- [ ] 確認画像は**実際の GLB を描画したもの**（コンセプト画像を確認画像にしない）
- [ ] manifest と ASSET_LIST を更新した
- [ ] 1層のファイルを変更していない（`git diff --stat` で `b1_ancient_forest/` が出ない）
- [ ] 作業は自分の作業ブランチで行い、development に直接入れていない。PR に「作った物・未完成の物・確認していない点」を書いた

## 9. 受け取った後（Claude が行う）

1. フォルダ・名前・寸法・原点・容量を確認する。合わない物は差し戻すか、直してよいかを確認する。
2. テーマ設定（`FIELD_3D_SPEC.md` §2-2）に登録し、マップ文字・物との対応を決める。
3. 動き（アニメーション・UV・粒子・反射）の再生を実装する（§6 の書式を読む）。
4. 1層が変わっていないことを確認する（`FIELD_3D_SPEC.md` §5）。
5. PR を作り、ユーザーの確認と承認を待つ。
