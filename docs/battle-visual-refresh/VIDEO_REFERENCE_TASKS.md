## 2. 担当分担

### GPT：表示・UI・アニメーション担当

- キャラクター立ち絵の表示仕様と素材要件（絵柄の最終決定・画像制作は素材準備後）

- スキル一覧・詳細・習得確認UI
- スキル使用時の表示演出
- ダメージ数値・被弾表示
- 攻撃エフェクトの視覚表現
- ユニオンスキルのカットイン・画面演出
- PC・スマートフォン向けレイアウト調整

### Claude：戦闘状態・データ・イベント連携担当

- 状態異常の識別子・付与・継続・解除状態のUI向け連携
- 既存インペリアル蓄積値・最大値・消費後の値のUI向け連携
- ターン開始・終了、行動、攻撃、スキル、回復、状態異常などのイベント発火点の整理
- 攻撃種別・攻撃者・対象・属性・確定ダメージ結果の演出側への受け渡し
- ユニオンスキルの実際の参加者一覧と発動情報の受け渡し
- 演出待ちによる二重行動・二重ダメージ防止

## 3. 連携手順

1. Claudeは既存コードを調査し、必要なイベント名・データ形式・発火タイミングを先に文書化する。
2. GPTはそのインターフェース案を確認し、UI・演出側の受け取り方を提案する。
3. 両者でデータ形式と責任範囲を確定してから、担当別ブランチで実装する。
4. 同一ファイルを同時編集しない。共有ファイルの変更が必要な場合は先に報告・調整する。
5. 各担当はPRでdevelopmentへ提出し、統合前に変更内容とテスト結果を明記する。

## 4. 共通の保護条件

- 既存のダメージ計算、命中率、行動順、SP増減、スキル効果、状態異常効果、敵AIを変更しない。
- セーブデータ形式・固定ID・既存素材を無断で変更・削除しない。
- 新規ライブラリ・CDN・外部サービスを導入しない。
- 表示演出と戦闘結果の確定処理を分離する。
- 演出終了後に操作ロック・DOM要素・タイマー等が残らないようにする。
- PCとスマートフォン双方で確認する。
- mainへの反映・公開はユーザーの明示承認が必要。

## 5. 参考資料の制約

YouTube URLとタイムコードは本書に記録したが、動画ファイル自体はリポジトリに配置していない。Claude/GPTが動画を直接参照できると仮定しないこと。文章化された要件を作業基準とし、映像の細部が不明な場合は推測せず確認事項として記録する。

キャラクター絵柄の刷新は、参考画像・制作素材・保存先・ファイル名・ライセンス等が確認できるまで最終素材の差し替えを行わない。仮素材を使う場合も本番素材と区別する。
