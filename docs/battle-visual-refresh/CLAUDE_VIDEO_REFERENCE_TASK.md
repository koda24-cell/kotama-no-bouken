# Claude担当作業指示：動画参考UI・戦闘演出のデータ連携

関連文書：VIDEO_REFERENCE_TASKS.md  
既存仕様：../battle-visual-reference/CLAUDE_SPEC.md  
参考動画：https://youtu.be/gir5chMdXaU

## 担当範囲

Claudeは戦闘状態・データ・イベント発火・演出側への連携を担当する。CSS、画像レイアウト、カットインの見た目そのものはGPT担当とする。

### A. 状態異常データ連携
- 既存の状態異常ID、付与・継続・解除タイミングを調査する。
- UI側がキャラクターごとの状態異常を取得できる既存データ経路を確認する。
- 既存経路が不足する場合は、最小限の読み取り用データまたはイベントを提案する。
- 状態異常の効果、発生率、継続ターン数、解除条件を変更しない。

### B. インペリアル連携
- 既存の蓄積値・最大値・増加条件・消費条件を調査する。
- UI側が現在値を取得できるようにするためのデータ経路を明確にする。
- 表示は既存仕様どおりSP攻撃コマンド右側の縦線本数を前提とし、新規ゲージや蓄積ルールを作らない。
- 既存実装や確定仕様が見つからない場合は推測で補完せず、未確定事項として報告する。

### C. ターン・イベントログ連携
- ターン開始・行動開始・攻撃・スキル・回復・状態異常・ターン終了の発火箇所を調査する。
- 表示側が既存ログの順番とタイミングを扱えるよう、必要なイベント情報を整理する。
- ログ文言・戦闘結果・ログ保存仕様を変更しない。

### D. 攻撃・スキル演出トリガー
- 通常攻撃、SP攻撃、魔法、敵特殊攻撃について、行動開始・命中・ダメージ確定のタイミングを特定する。
- 攻撃者、対象、攻撃種別、属性、確定した結果など、表示に必要な最小情報を整理する。
- 表示側のイベント待ちによって戦闘処理が二重実行されない構造を確認する。

### E. ユニオンスキル連携
- 実際に参加したキャラクター一覧と発動情報を表示側へ渡す。
- 参加者を演出側で再選定させない。
- 発動・ダメージ確定・演出開始／終了の関係を整理する。
- 既存の参加条件、効果、ダメージ、行動順を変更しない。

## 最初に提出するもの（コード変更前）
1. 関連する既存コードの場所・関数名
2. 既存データの形式と取得方法
3. イベント名・payload案・発火タイミング
4. GPT側との責任境界
5. 既存仕様との不一致・不足・競合
6. テスト方法

Claudeは最初にこの連携設計をGPTへ共有し、共通インターフェースを合意してから実装に進む。既存処理を大きく変更する必要がある場合は、変更前に影響範囲と代替案を報告する。

## 完了条件
- 状態異常・インペリアル・ログ・攻撃結果・ユニオン参加者が既存戦闘データと一致する。
- 演出連携によって行動順、ダメージ、SP、状態異常、敵AIが変化しない。
- 二重行動・二重ダメージが発生しない。
- 確認済み／未確認／問題あり／条件付きのテスト結果を分けて報告する。

## 禁止事項
- GPT担当のUI・CSS・画像レイアウト・アニメーションを独断で実装しない。
- ダメージ計算、命中率、行動順、スキル効果、敵AI、セーブデータ形式を無断変更しない。
- 既存のCLAUDE_SPEC.mdと矛盾する場合は上書きせず、差分を報告する。
