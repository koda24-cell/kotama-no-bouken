# 第3階層「遺跡都市」3D品質監査（2026-11-10）

## 確認した実装
- development の `field/field-3d-b4-b5-map.js` は第3階層を `mist` として扱い、背景・霧・床・壁が緑系。樹幹・樹冠、結晶、天井の鍾乳石状装飾が配置される。
- Draft PR #162 は同ファイルに石畳の目地、壁際の柱、梁、帯状装飾、浮き彫りを追加し、色彩を石造都市へ変更する。現時点では development 未反映として差分を確認した。
- 同ファイルが第4・第5階層のテーマも扱うため、変更時は階層3専用条件に閉じること。

## 優先課題と実装案
1. **立体的な遺跡都市**: 壁面に貼る単純な帯だけでは街並みにならない。壁沿いに建物ファサード（壁厚、窓の凹み、崩れた軒、階段状の石積み）をモジュール化する。通行マス中心に配置しない。
2. **神殿・門のランドマーク**: 既存の出口・ボス・階段オブジェクトの位置を参照し、専用の非衝突視覚モデルを追加する。ランダムな通路中央配置は禁止。
3. **街路の読みやすさ**: 石畳の目地は現行案の浮いた細長いBoxGeometryより、床の法線・テクスチャ表現を優先。遠方でちらつかないか確認する。
4. **景観の差別化**: 霧を完全に消すのではなく、遠景の建築シルエットが見える濃度へ調整。暖色の灯火と冷色の環境光で探索方向を誘導。
5. **パフォーマンス**: `batchStatic()` の InstancedMesh 化を維持。描画負荷、頂点数、テクスチャサイズ、スマホでのFPSを計測する。

## PR #162のレビュー指摘
- `if (false && mist ...)` による樹木抑止は、条件式の削除・階層別分岐への整理が望ましい。
- `ornaments++` が実際に配置しない装飾でも加算される分岐があり、デバッグ指標として不正確になる。
- 目地BoxGeometryは床面との高さ差が小さく、斜め視点でのちらつき・浮き上がりをブラウザ確認する必要がある。
- `dispose()` は共有ジオメトリとマテリアルを再利用する設計。新しい固有ジオメトリの所有権を明示し、階層切替でリークさせない。

## 安全確認の条件

- 第4・第5階層の分岐と表示が差分で変化しないこと。
- 神殿の入口、ボスゲート、階段、NPC、スイッチ、看板、宝箱の視認性と操作性を確認。
