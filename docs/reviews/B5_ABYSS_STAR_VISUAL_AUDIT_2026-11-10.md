# 第5階層「奈落の星界」3D品質監査・統合前チェック（2026-11-10）

## 確認対象
development の `field/field-3d-b4-b5-map.js` を確認。現行の第5階層は暗い紫紺の背景（0x050514）、霧（0x10102a / density 0.022）、紫の発光結晶、星界用の浮遊粒子、ボス位置の玉座GLBを使用する。移動判定はマップが正とされ、3Dは視覚表現。

## ユーザー確定の美術方針
- **第5階層（通常迷宮）**：奈落、星空、深淵、浮遊岩盤、遠景の奥行き。星環・星片・星座状の鉱脈はこの領域に適用。
- **魔王城（決戦建築）**：巨大な暗黒神殿。高い柱、ゴシックアーチ、シャンデリア、鎖、青緑の光、橙の蝋燭。通常の星界通路全体を神殿化しない。
- 現行ボスマスの玉座を「魔王城全域の実装完了」とみなさない。魔王城の配置・進行仕様は別途確認。

## 現行コードで確認した品質上の課題
1. 通常通路は全マスに床・天井があり、床の外側や天井の先に広がる「底なしの奈落」「星空」はほとんど表現できない。視覚上の抜けを作る場合でも壁セル・通行判定を変えない。
2. `batchStatic()` はジオメトリ・マテリアルごとに全域を単一 InstancedMesh にまとめ、`frustumCulled=false`。表示範囲外の描画負荷が増える可能性がある。チャンク分割は別PRで計測してから検討。
3. `g.lights` には最大28の結晶光源を追加する。追加の局所光源を無制限に増やさず、発光マテリアル主体の演出を優先。
4. `dispose()` は追加ライトの off と root の除去を行うが、`localGeometries` と外部GLBの破棄はこの関数では行わない。既存の共有素材管理との関係を調査してから変更する。
5. `build()` には非同期GLBロードがある。階層切替中にロード完了する場合の描画先rootの整合性は未検証。
6. 現行の装飾配置は決定論的ハッシュにより再現可能。新規装飾でもこの性質を維持する。

## 次回の安全な実装候補
**星界の遠景レイヤー（最優先）**：既存の床・壁・天井・通行判定を変更せず、遠方の星粒と低密度の浮遊岩片を視覚専用の独立グループに配置する。マップ外側への視線の抜けは実画面を確認してから判断。追加動的ライトは0、決定論的配置、ジオメトリ共有、階層切替時の破棄、描画負荷の計測を必須とする。既存の高所星片PR #171とは位置と役割を分ける。
