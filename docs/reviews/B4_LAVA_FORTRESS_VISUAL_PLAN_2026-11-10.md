# B4 竜炎の迷宮：溶岩城塞の景観実装計画（2026-11-10）

## 現状の確認
development の `field/field-3d-b4-b5-map.js` は `area === 4` で火山色の霧・岩盤・溶岩とマップ駆動3Dを生成する。背景GLB候補とボス障壁はあるが、ユーザー参考画像にある「溶岩の大河、尖塔群、城塞、石橋、遠景の巨大都市」という景観の達成は、実ブラウザ画像なしでは確認できない。

## 今回の判断
第4階層PR #159 #164 #167 #172 #174 #178 と第3/5階層PRが共有描画ファイルを編集しており、追加改修を同時に積むと競合・取りこぼしのリスクが高い。今回は共有JSを変更せず、次回の安全な実装に必要な構成・受入基準を確定する。

## 優先する3D景観（参考画像に沿う）
1. **遠景城塞**：黒い玄武岩の尖塔、ドーム、城壁、アーチを組み合わせた非接触の背景グループ。最初は低ポリゴンのプロシージャル模型を1組だけ設置し、通路からのシルエットを確認。
2. **溶岩の河川**：現行の溶岩マス描画を壊さず、背景として連続する発光帯と暗い冷却岩盤を追加。マップの `*` / `~` と歩行判定は変更しない。
3. **橋のシルエット**：通行可能な新しい橋を作るのではなく、遠景の非接触アーチ橋として配置。既存の移動・FOE経路に干渉させない。
4. **遠近感**：カメラの視界・霧の仕様を守り、近景の岩盤、中景の城壁、遠景の尖塔を明暗で分離。動的ライトの無制限追加は禁止。

## 次の実装単位
- 第1段階：B4専用の城塞シルエット1組を独立したモジュールとして追加。共有JSには小さな呼び出し口だけを設け、先行PR統合後にリベースする。
- 第2段階：橋・アーチの遠景バリエーションと溶岩反射を追加。
- 第3段階：実機スクリーンショット比較とスマートフォンFPS測定後に密度調整。

## 受入基準
- B4以外では新しい城塞が表示されない。
- 通路・階段・FOE・イベント・セーブ・当たり判定は一切変更しない。
- 遠景装飾にインタラクションや衝突判定を追加しない。
- 新規ジオメトリとマテリアルの破棄・再利用を検証する。
- desktop/mobileで描画、クリッピング、FPS、フロア切替を確認する。
- 参考画像と実画面を比較し、城塞のシルエット・橋・溶岩の奥行きが認識できることを確認する。
