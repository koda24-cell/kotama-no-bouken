## 1. 物語と環境史（提案設定）
1. 旧文明：高架歩道、鉄筋コンクリート建築、都市広場、道路・給排水・橋梁・工業設備が存在。
2. 崩壊：地盤沈下＋構造体の疲労＋局所的な外力により橋梁や屋根が破断。崩壊はランダムな穴ではなく、支持点・鉄骨接合・スパン中央など力学に関係する箇所へ寄せる。
3. 侵食：雨が縦方向に流れ、水平面のくぼみに水が溜まり、ひび割れと目地へ植物が侵入。錆汁が鋼材から下方向へ流れ、日陰の下部に苔が帯状に残る。
4. 現在：半ば破壊された都市に樹木、下草、つる、シダが入り込み、空から差し込む光で探索経路を可視化。
5. 大きな空間構成：安全通路→小広場→崩壊高架→緑の吹抜け→都市の中枢を徐々に露出。目的地を視認できるランドマークを置き、単調な四角い廊下の連続を避ける。

## 2. 地形・構造設計
- 共通接続タイルは既存の2m×2m規格を保持（PR #353/#376）。接続面の幅、高さ、南北/東西方向は現行の引き継ぎと一致させる。勝手に寸法を再定義しない。
- 建物や路地のバリエーションは同じタイルでも「周囲の付加構造」「視線遮蔽物」「高低差」「床面の汚れ」「光」で差を作る。崩壊で通行可能領域を塞がない。
- 構造の階層：A 大スケール（橋、塔、倒壊ビル）/ B 中スケール（梁、踊り場、手すり、根塊）/ C 小スケール（欠け、腐食、泥・コケ）。遠景シルエットと近景の質感をそれぞれ評価。
- 破損は3種を組み合わせる：(1) 構造上の大きな欠損、(2) 不規則な中規模亀裂と層状剥離、(3) PBR normal/roughness/microdetail。微細な球状粒を散布してごまかさない。
- 支柱/手すりは必ず実床形状と干渉・接合し、浮遊0。破断箇所は曲げ、露出鉄筋、断面、錆汁と周辺破損を連動させる。
- 進路判定上の空隙/段差は見た目と当たり判定が一致するようClaude連携時に確認。

## 3. ベースの色とトーン（初期提案、テストレンダーで調整）
- 主材：温かみある灰褐色の古いコンクリート。中立光で色が灰色/茶色に寄りすぎない。
- 二次材：酸化した鉄の暗褐色とくすんだ橙。錆は水垂れ経路に沿って限定的に。
- 植生：日向はやや黄色い鮮緑、陰は青みを抑えた深緑。鮮度と彩度にグラデーションを付ける。
- 割れ内部：表面より暗い低彩度の灰。黒い線で縁取るのではなく、深さとAOで成立。
- 指向：大きな材色の比率を揃え、すべてのタイルに同じカラーパレットと露出基準を適用。基準写真とは別にニュートラル照明の材質検査レンダーを作る。
- 参考作品の評価軸：BotW＝遠景/遊びやすさ、原神＝植生と色彩のまとまり、Endfield＝構造の存在感。いずれもブランド固有の配置/デザインを転用しない。

## 4. マテリアル技術仕様
- glTF 2.0 Metallic-Roughnessを基本。BaseColor (sRGB)、Normal (OpenGL tangent space, Non-Color)、Roughness/Metallic/Occ (linear)をUV付きで埋め込み、出力GLBを再読み込み検査。
- Blender Noise/BumpだけではglTFへの転送を保証しない。写真PBRの法線とマクロジオメトリを分離し、穴や輪郭変化は実メッシュで制作。
- 参考材候補（全て公式Poly Haven、CC0と記載されているもの。導入/実画像閲覧/解像度/取得成否は今後個別確認）:
  - Cracked Concrete: https://polyhaven.com/a/cracked_concrete （床の大規模亀裂、2m幅、Normal GL/Height/Rough）
  - Concrete Layers: https://polyhaven.com/a/concrete_layers （層状の剥離・型枠/壁、1.5m幅）
  - Chipped Concrete: https://polyhaven.com/a/chipped_concrete （欠け・多孔質）
  - Concrete Moss: https://polyhaven.com/a/concrete_moss （湿潤床・苔の局在、3m幅）

- 近接で見える面と裏面は同じ品質。法線方向・ジオメトリ破断面の裏表/厚みを確認。UV seamやタイリングの不自然な反復はマクロ汚れマスクで軽減。

## 5. 植生と自然の因果関係
- 森：下草→低木→幹→樹冠の4階層。樹冠は視界や目的物を隠し過ぎない。
- 遺跡：根は目地や欠損部から出て地面に固定される。壁を突き抜けたり宙に浮くつるを作らない。
- 苔は水平湿潤面、陰面、排水周りに帯状に置き、小さな緑の点や虫状の突起は配置しない。
- 大木の根が構造体を押し広げた場合は、そのすぐ隣のひび割れ・剥離・傾きまで作る。
- 地形は岩、土、人工コンクリートの接地部分を遷移ジオメトリやマスクでつなぐ。四角いパネルの輪郭が残らないよう隣接検査。

## 8. 品質ゲート
- G0 source: 参照/作者/権利/材質ライブラリ記録。Pinterestは資料リンクのみ。
- G1 geometry: silhouette、支持機構、厚み、接地、凹凸/実欠損、面の裏返りをチェック。
- G2 textures: UV/画像Normal/roughness/色空間/実寸テクスチャスケール/埋込を検査。
- G3 real render: Blenderで正面/側面/斜め、できれば真上・接合時・ゲーム目線をPNG保存。Blenderログ、生成コードSHA、各ファイルSHAを記録。
- G4 glTF reimport: GLB再読込とブラウザThree.js表示で材質一致、タイリング、シルエット・接地/スケール確認。
- G5 objective QA: 存在/形式/ハッシュ/画像サイズ、黒つぶれ・白飛び、画面占有率、各方向、マテリアル、法線、ボックス寸法。
- G6 artistic QA: コンセプト、世界観、距離別の読みやすさ、破損の自然さ、汚れの因果、光/色の一貫性を人が確認。自動スコア単独で完成としない。
- G7 approval: ユーザーが実画像で承認した版のみ GLB/PNG/manifestを正式アセットフォルダへ別PR昇格。
- 3層でのcheckpoints/restartは未検証。5層玉座runの実績をそのまま3層で有効と言わない。反復上限/安全停止/中間保存を個別に移植して実証する。

## 9. 制作体制（役割分担の提案）
- アートディレクション（GPT）：世界観、採用基準、資料台帳、レビュー。
- 構造モデリング（Blender Python/Actions）：モデル生成と実レンダー（実行成功は毎回ログ確認）。
- テクスチャ研究（PBR/ライセンス管理）：CC0候補、normal/baked roughness、hash。
- QA（画像/コード）：3方向比較、実GLB検証、破損接合チェック。
- ゲーム統合（Claude）：**承認後**のみGLB/PNG/manifestを受け取ってThree.js接続。ClaudeがBlenderを使ったと記述しない。
- 最終承認：ユーザーのみ。複数AIやエージェントの実並列稼働は環境で実際に確認できた場合だけ報告。
