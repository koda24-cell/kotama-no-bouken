## 2. トーンと配色（全アセット共通・統一ルール）

既存の玄武岩テクスチャ（`assets/textures/floor4/basalt-charcoal-01`）と、GPTのV16／P1〜P3／トロッコV32の色を基準にそろえる。

| 役割 | 色（sRGB） | 明度の上限 | 備考 |
| --- | --- | --- | --- |
| 玄武岩・黒岩 | #1d1a19〜#2e2926 | 0.20 | 溶岩の照り返しでだけ赤く見える |
| 灰・積もった塵 | #5d5853〜#7a736b | 0.45 | 上向きの面と凹みにだけ |

| 煤けた木 | #2a1d15〜#4a3626 | 0.30 | 炭化部は #120d0b。木口と割れは少し明るく |

- 発光する面は「割れ目の内側」「燠火の芯」「結晶の内部」に限る（BotWの溶岩岩、Pinterest #41 #55 #64 の見え方）。

## 3. 経年劣化・欠けのルール（すべてのアセットで必須）

1. **形の欠け（シルエット）**：角・縁・端を必ず崩す。欠けは外形の5％以上の大きさにし、遠くから分かるようにする（ガイドライン2章）。木は折れ口をささくれさせ、石と骨は欠片の断面を見せる。
2. **角の摩耗**：鉄は角だけ地金が出て明るく、木は角が丸まって明るく、石は角が欠けて新しい断面になる。
3. **煤のグラデーション**：熱源に近い側・上の方を暗く。火鉢の内側、看板の下端、支保工の溶岩側。
4. **灰と塵**：上向きの面と凹みに、薄い灰色を積もらせる。
5. **熱による変色**：燠火・溶岩のそばの鉄は、青黒〜赤茶に焼けた色。木は炭化して亀甲状に割れる。
6. **使われた跡**：工具の柄の手垢による艶、車輪の摩耗、ロープのほつれ。
7. 劣化のかけ方は、すべてのアセットで同じ材質関数（`tools/b4-props/common.py`）を使い、トーンがそろうようにする。

## 4. テクスチャ調査と使う素材

Pinterestの画像はテクスチャに流用しない。直接使うのは、一次配布元で確認したCC0素材と手続き生成だけ。

| 材質 | 元にする素材 | ライセンス | 加工 |
| --- | --- | --- | --- |
| 錆びた鉄板 | Poly Haven `rusty_metal_03` | CC0（https://polyhaven.com/license） | 暗く、彩度を下げる。角の摩耗マスクで地金を出す |
| 粗い錆 | Poly Haven `rust_coarse_01` | CC0 | 鎖・金具の錆の島に使う |
| 古い木材 | Poly Haven `wood_planks` ／ `raw_plank_wall` | CC0 | 煤で暗くし、炭化マスクで亀甲割れと黒を重ねる |
| 黒岩・母岩 | Poly Haven `rock_face_02`（GPT V33と同じ） | CC0 | 既存のB4岩と同じ色にそろえる |
| 炭化木・骨・鱗・結晶 | 手続き生成（ボロノイ割れ、ノイズ、ポインティネス） | 自作 | — |

- 取得：Actions のなかで Poly Haven の公式ダウンロード（`dl.polyhaven.org`）から1K/2Kを取り、sha256 と URL を各アセットの manifest に記録する。
- 仕上げ：手続きの材質ノードは glTF に出ないので、**アセットごとに Cycles でベイク**し（Base Color／Roughness／Normal／Emission、AOはBase Colorに弱く乗算）、画像テクスチャの Principled BSDF に差し替えてから GLB に書き出す。

## 6. 制作の手順（1アセットごと）

1. **参考を決める**：上の表のPinterest番号をシートで見直し、形・寸法・劣化の要点を `tools/b4-props/build_<id>.py` の先頭に書く。
2. **ブロックアウト**：実寸で大まかな形を作り、studio照明で正面・横・斜め・上をレンダー。比率とシルエットを確認する。
3. **詳細形状**：欠け・ささくれ・リベット・溝など、形でしか出せない細部を作る（ノーマルマップに頼らない大きな欠け）。
4. **材質**：共通の劣化関数で材質を作る → ベイク → 画像テクスチャに差し替え。
5. **レンダー確認**：`volcanic`（暗い洞窟＋溶岩の赤い照り返し＋燠火）と `studio` の両方で、4方向＋寄り。
6. **自己レビュー**：下の品質ゲートを1つずつ確認。足りなければ2〜5を繰り返す（版を上げる）。
7. **独立レビュー**：制作に関わっていないエージェントが、レンダーと参考シートだけを見て点数をつける。8/10未満なら作り直す。
8. 合格したら manifest の `approval` を `CLAUDE_REVIEWED`（ユーザー未承認）にして次のアセットへ進む。

## 7. 品質ゲート

| 項目 | 合格の条件 |
| --- | --- |
| シルエット | 4方向のどれでも、単純な箱・円柱に見えない。欠けが遠くから分かる |
| 実寸 | 人の身長（1.6m）と並べて不自然でない。原点は底面中央 |
| 劣化 | 3章の1〜5がすべて入っている。新品に見える面がない |
| トーン | 2章の明度上限を守る。他のアセットと並べて浮かない |
| 発光 | 割れ目・芯・内部だけ。面全体が光っていない |
| 技術 | 三角形数とテクスチャの上限以内。マテリアル3個以下。GLB 1.5MB以下（大型は3MB以下）。法線の裏返り・穴がない |
| ゲーム内 | Three.js（r180）で読み込み、B4の照明で撮影して確認（統合時） |

## 8. 配置ルール（統合時）

- 小物は「場面のセット」で置く：
  - 採掘現場（支保工＋トロッコV32＋レール＋工具＋木箱）
  - 休憩所（火鉢＋樽＋ランタン）
  - 竜の痕跡（爪痕の岩＋鱗＋焼け木）
  - 巣の手前（頭骨＋肋骨＋卵殻＋鎖）
- 入口側→奥で、人の痕跡から竜の痕跡へ密度を入れ替える（1章）。看板は巣の手前の分かれ目に1つだけ。
- 通路・敵・イベントの物を隠さない。通行判定とFOEの動きは変えない。
- 同じアセットを並べるときは、回転・縮尺（±12％）・欠けのバリエーションを変える。
- 描画負荷：同じGLBはインスタンス化し、遠くでは小物を消す（距離で表示を切り替え）。B4全体の三角形数は、#203で決めた目安（平均40万・最大95万）に合わせる。

## 9. チーム体制

- **リード（Claude本体）**：共通ハーネス、最初のアセット（火鉢）で品質の基準を作る。全体のトーン確認、統合。
- **制作担当（サブエージェント、1人1アセット）**：この設計書と参考シートを読み、6章の手順で制作。ブランチ `feature/ai-claude-b4p-<id>-20261119`。
- **レビュー担当（サブエージェント、制作に関わらない）**：レンダーと参考だけを見て採点し、直すべき点を具体的に返す。
- レンダーは GitHub Actions のヘッドレス Blender（4.2.3、Cycles CPU）で行い、結果をブランチへコミットして Git 経由で確認する。Claude が Blender を直接操作できるとは主張しない。
