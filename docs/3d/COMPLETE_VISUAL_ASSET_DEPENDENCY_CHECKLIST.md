# 3D・VFX制作時の依存素材セット確認（候補・未承認）

## 目的
見た目が完成していた表現を、コードだけ移植してテクスチャ・発光・VFXを失う事故を防ぐ。既存の承認済み素材は変更しない。

## 作業前に確認するもの
1. 現行development・作業ブランチ・関連PRのコード、既存レンダリング、承認状況を確認する。
2. シーンが参照するGLB、PNG、Emission、Normal、Roughness、Alpha、シェーダー、マテリアル、ライト、VFX、アニメーション、設定値、依存ライブラリを列挙する。
3. 参照ファイルの実在、取得元、ライセンス、バージョン、パス、取得後の安全検査を確認する。欠損した素材は欠損と記録し、代用品を完成扱いしない。
4. 依存素材のセットが揃ってから統合候補を作る。元の完成表現と同条件・同角度で比較し、質感・発光・奥行き・明滅・画面端を評価する。
5. 正面・側面・斜め／背景なら360度8方向と移動後を実レンダリングし、画像を目視確認する。不合格なら修正・再レンダリングを繰り返す。
6. モデルと付随テクスチャ/VFXをまとめて台帳化する。GitHub Actions Artifactsは一時保管、正式保存はユーザー承認後のみ。

## 第5層窓背景での失敗事例
- 元のプレビューは `field/assets/b5-distant/facade020c-windows.png` を参照するが、確認したdevelopmentには画像が存在しなかった。
- 元の `field/b5-distant-fog-background.js` だけを使い、実物のEmission画像を復元せず仮の窓を重ねたため、元の発光表現を再現できなかった。
- ambientCG Facade020Cを候補元として確認し、ライセンス・実ファイル・発光画像・安全検査・レンダリング比較が揃うまで『復元済み』とはしない。
