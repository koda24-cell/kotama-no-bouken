## ユーザーが求める配置・ゲーム仕様

- これらの素材は第2階層「水源（氷）」の水面エリアや、プレイヤーが進行できない景観エリアに配置できるようにする。
- 通常の水面は**非通行**。水上を歩ける地形を暗黙に生成しない。橋・渡渉可能な浅瀬・イベント用の通路は明示的に別管理する。
- **水面がマップの外（未生成領域・場外・空白）と直接隣接してはいけない。** 最外周には必ず岸・岩・崖・壁などの終端地形を確保し、水面を閉じ込める。
- マップ境界の水面は生成段階で禁止し、外周から最低1タイル分（必要なら視覚的な厚みの分だけ追加）の岸・壁バッファを設ける。非進行エリアに水面を置く場合もこの規則を適用する。
- ただし「水面は必ず完全に内陸の池にする」という意味ではない。川・水路・岸辺・水が陸へ侵食した浅瀬などは許容する。**マップ外への開口だけを禁止**する。
- 地形の見た目として、水が陸の岩の下に侵食し、陸上に水路や水たまりが伸びる表現を維持する。
- 長い固定一枚メッシュではなく、1マスごとに独立したGLBを配置し、ランダムマップ生成時に組み替えられるようにする。
- 既存マップ・3D描画・衝突判定・セーブデータ・戦闘処理を維持。変更はdevelopment向け独立PRでレビューする。

## 接続マスクと検証

water_tile_00.glb ～ water_tile_15.glb は N=8 / E=2 / S=1 / W=4 のビットマスク。ビットが立つ方向は水路の接続側。番号は通常のNESW順の2進数ではないので注意。

- 隣接セルAとBの境界で A.E == B.W、A.N == B.S を必須にする。
- マップ外周に向かうビットは必ず0にする。ただしビット0でも水面の見た目がタイル端まで到達しないことを実レンダリングで検証する。
- 地形タイプ（WATER / LAND / WALL / BRIDGE / DECOR）と通行可否は別データにする。GLB名や見た目だけで通行可否を決定しない。
- ランダム生成の例: 通行可能な探索領域と非通行水域をまず決定 → 水域を外周から切り離す → 隣接方向からmaskを計算 → GLBを配置 → 境界/衝突/視覚継ぎ目を検証。
- 水域をマップ端まで延ばしたい演出が必要な場合、外側に岸壁・崖・遮蔽地形を追加する。場外へ開いた水面のままにはしない。
- 単体タイル表示も許容するが、単体のwater_tile_00.glbの実際の水量・表示を検証し、必要なら単体用の専用地形を別途作る。見た目の成立を未検証のまま保証しない。
- 出口、階段、宝箱、FOE、イベントの必須導線を水で塞がないこと。到達可能性のテストを行う。
- 16種のGLBは現時点で実生成済みだが、実ゲーム内での全パターン接続・描画性能・境界判定は未検証。

## 実装の確認項目

1. 通行可能な探索経路を保ったまま、非進行エリアと水域にモデルを配置できる。
2. すべての水域の外周が岸・壁などで閉じており、マップ外と直接隣接しない。
3. N/E/S/Wの開口が隣接タイルと一致する。T字、十字、行き止まり、単体をテスト。
4. 既存の水辺演出、岩盤、侵食、浅瀬の見た目を維持する。
5. マップ再生成・セーブ/ロード・移動衝突判定・描画負荷を検証する。
6. 配置のゲーム内スクリーンショットを提出し、ユーザーの確認を得る。
