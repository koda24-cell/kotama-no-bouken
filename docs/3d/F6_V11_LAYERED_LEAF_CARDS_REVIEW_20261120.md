# F6 V11 葉束の平面化を改善する試作 — NOT_APPROVED

## 目的
V10の660枚の葉カードが重なって1枚の緑の面に見える問題を修正。これは失われた真正V08ではなく、**V27幹枝 + V31代用画像のV08風復元候補**の派生。

## 実際に行ったこと
- V10の元GLB SHA256: `97ab5a68e7570620d5d64bd5b9eef4ffc381863fc7bdb161b8d3da08a154b766`
- 幹枝・主枝13本のジオメトリを一切変更せず保持。葉カード**660枚も削除せず保持**。
- 1枚ごとに縦軸まわり ±43°、横軸まわり ±14° の向きを変化させ、3つの奥行き層で配置差（約4〜6 cm）をつけた。葉の形状に0.94〜1.08倍の微細なバリエーション。
- 内側の葉色を0.87倍、外側を1.12倍、中間を1.0倍として色調差を設定。元テクスチャのアルファ値を維持。
- 6種類の葉群を3層に分けた計18メッシュ群。glTFのノード数233→245。
- V11 GLB SHA256: `4308420da139c4ca795b06123418079b9da096c191265e937fcf21ce5741b86f`
- VTK 9.6.2 / EGLで**正面・側面・斜め・枝接写の実GLBを再レンダリング**。V10と同カメラで比較JPG4枚。Blender5.3およびThree.jsでのV11検証は未実施。
- 技術QA: 660カード・主枝13本は維持、原本とモデル外形の差は0.18m以内のassertに合格。
- 美術QA: 葉群に色差・向き差は生じたものの、**中央がまだ大きな緑の面に見える。不合格。** 今後はカード単位の微小修正ではなく、葉塊の中心座標を枝単位で分け、塊同士に見える重なりと奥行き・抜けを設計しなおす。中心に大穴を作らないこと。
