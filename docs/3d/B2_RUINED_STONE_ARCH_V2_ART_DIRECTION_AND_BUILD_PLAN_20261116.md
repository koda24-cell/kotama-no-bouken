## 3. 建築構造と破壊の整合性
### 残すV1の構成
1. 中央開口を持つ半円アーチ、左右高さの異なる石柱、積石コース、左右非対称の欠落、敷石、瓦礫。
2. 既存の石材メッシュと配置は保持。削除・上書きではなく、追加造形を別命名の独立オブジェクトで行う。
3. 可視的な破断部に未支持の“浮遊石”が出ていないか、画像と3D位置で評価。

### 形状変更の基本単位
- **大損傷（約60%の視覚的重要度）:** 片側肩石の崩落、対角に割れた柱上部、アーチ外周の欠損、斜めに倒れた大きな落石。V1の開口を塞がない。
- **中損傷（約30%）:** 迫石と柱石の不規則な角欠け、継ぎ目の深さ、部分的な座屈、斜めの割れ面。
- **微細損傷（約10%）:** 釘傷/風化穴/微細亀裂/砂岩の粒、湿気によるエッジ濃色化。
- 浮岩・正方形の単調な角・細かい豆粒のような瓦礫・貼り付けた楕円状の破損は不合格。
- 実際に削れた凹部は将来的に非破壊Booleanモディファイア・切削専用派生モデル等で制作し、単なる表面石の追加を本物の欠損と呼ばない。
- 石材の構造荷重が認識できるよう、アーチ両端の迫石から支持柱への伝達を残す。浮いている上部要石は不要な支持ブロックで完全補修せず、破断として説得力が出る切れ目を設ける。

## 4. 色調・環境ライティング
- ベースの石材: 乾いた灰褐色 #77746d、陰 #494d50、暖色砂岩 #8d806c、磨耗した面 #a69c8d は**目標の仮色**。環境光/色管理下で調整し固定値とはしない。
- 第2層共通: 寒色の洞窟環境光、湿った石の暗色面、局所的な暖色の反射。青い氷の装飾は点景でありアーチ全体を青く染めない。
- 他の石橋・柱・水門のマテリアルとの視覚差は、正面・斜めの比較スクリーンショットで確認。
- コンセプト照明と中立の材質検査照明を分ける。暗さで粗い形状を隠さない。

## 5. PBRマテリアル調査・適用候補
- **Poly Haven [Stone Block Wall](https://polyhaven.com/a/stone_block_wall)**: 古代の荒い石積み、彫り傷、継ぎ目。主材候補。ただし既存モデルの石ブロック自体の継ぎ目はメッシュで表現し、壁画像の継ぎ目を各ブロックへ全面貼付して二重の目地にしない。
- **Poly Haven [Stone Wall](https://polyhaven.com/a/stone_wall)**: 風化、ひび、角の劣化、比較の基準。
- **Poly Haven [Rock Wall](https://polyhaven.com/a/rock_wall)**: 水辺に近い粗い岩や背景岩の比較。
- **Poly Haven [Japanese Stone Wall](https://polyhaven.com/a/japanese_stone_wall)**: 大石の向き・目地の参考であり採用未決。
- 公式ライセンス: https://polyhaven.com/license (CC0、商用・改変・再配布可)。https://docs.ambientcg.com/license/ (ambientCG配布物CC0)。
- 必要マップ: **Base Color, Normal (OpenGL), Roughness, AO, Height**。メッシュの大きな欠けはジオメトリ、小さな凹凸のみNormal/Height。
- ブラウザGLBへの引き渡しを考慮し、NormalやRoughnessは画像としてノードにつなぎ、Three.js GLTFLoaderで実際に読み込めることを確認する。Blender内だけのNoise/BumpはGLBにそのまま焼き込まれると仮定しない。
- 現行の256px手続き生成アルベドは暫定。実PBRを使う場合は公式URL/ライセンス/ハッシュ/解像度を記録し、色味とUVスケールを評価後に採用する。現段階では外部ファイルの取得・実装成功を主張しない。

## 6. アセット互換性と制作工程
- **1素材単位の工程:** 旧GLB・PNG確認 → PinterestとPBR検討 → 構造設計 → V2形状追加 → Blender正面/側面/斜めPNG → 自己評価 → 次Pass → ユーザー承認 → GLB/PNG/BLEND/manifest/制作メモを正式保存。
- GLBには読み込み用の実寸、原点、石材ごとの材質、UV情報を保持する。ゲーム内通路マスに入るかはタイル座標と当たり判定で別途検証。
- ソース変更はDraft PR #401にのみ追加。完成資産や既存ゲームファイルには影響させない。
- 毎レンダー後のQA項目: 3方向PNGの存在とフォーマット、画像が空でないこと、GLBとBLENDの存在・hash、石材の浮遊・干渉、背景の穴、シルエット、テクスチャ反復感、白飛び、フレーム占有率、推定面数/ファイル容量。
- 初回の実際のBlender PNGとユーザー承認が確認できるまでは **NOT_APPROVED**。GitHub Actions Artifactは短期レビュー専用。
- checkpoint/別ジョブ再開はB5専用実績。B2では現時点未検証。B2用に導入する場合はハッシュ付きのソース照合を先に実装・テスト。

- 石材のベース色・ラフネス・ノーマルが既存第2層素材と統一される。

## 9. 第2層ダンジョン全体への接続設計（将来の個別制作）
本アーチを完成させた後、**個別に**制作するモジュールの順序と関係。既に完成済みの橋・祭壇・水面・氷岸・石造遺跡V4を作り直さず、利用しながら不足部分のみ増やす。

1. **古代石造アーチ**（今回）: 石橋入口・分岐のランドマーク。中央は進行可能な開口として保持、倒壊石は通路を塞がない配置も用意する。
2. **崩れた橋接続部**（次候補）: アーチ基礎と橋の床が切れて見えないように、敷石と侵食溝を連続させる。接続の上下左右に意味を持たせる。
3. **氷結水車・洞窟**: 既存Pass8の大規模構造を保持し、水の流れ、駆動軸と壁への支持、割れた木羽根、氷の厚みのばらつきを確認。
4. **洞窟と遺跡の境界**: 岩肌から人工の石積へ漸移させ、鋭い直線的な境界を避ける。
5. **水源・岩岸・氷岸・遺跡の地面**: 既存9パターン・12タイルなどの資産台帳との整合確認後に必要なつなぎ部品だけ制作。

### ランダム迷宮とゲーム表示
- 1マスごとの接続方向(北/東/南/西)をmanifestに持ち、開口/閉塞/方向別の状態を確認できるようにする。
- 水と陸が不自然に直接隣り合う問題を避け、侵食された岩岸/水際タイルを必ず仲介させる。
- 背景・ランドマークは遠景/近景の両方で成立させ、狭い一人称視点からも物体の大きさが感じられるよう調整する。
- 実寸m・原点・前方軸・地面高さ・水面高さ・橋接続位置はGLB/manifestから検証可能にする。現行アーチV1の寸法は暫定であり、正式採用前にゲームの1マスタイル仕様と突き合わせる。
- 破片数やポリゴン数の最適化を最初の造形品質の代償にしない。ただし衝突・視界・ロード/メモリを最終ゲートとして後から必ず評価する。
