# 3Dモデル制作時の参考資料・CC0素材活用ルール

> **適用範囲:** 『コタマのぼうけん』の全階層・全3D素材。GPT、Claude、Codex、他チャットでの作業開始時に読む。
> **入口:** リポジトリ直下 `AGENTS.md` → 本ファイル。
> **状態:** 参考元の候補を整理したガイド。個別素材の取得・ライセンス確認・モデル組込は別途実施する。

## 作業前に必ず確認すること
1. `AGENTS.md`、`docs/3d/BLENDER_DOCKER_HANDOFF.md`、`docs/3d/ASSET_PROMOTION_POLICY.md`、このガイドを読む。
2. `development` と関連作業ブランチ・PRの最新状態を確認する。
3. **画像参考を探す場合**は `https://github.com/koda24-cell/pinterest-reference-library` の `AGENTS.md`、`README.md`、`handoff/README.md` と対象タスクを先に読み、Pinterestを優先する。取得・採用判断・GPT/Claude間の引き継ぎは同リポジトリに記録する。
4. **モデルやテクスチャの実ファイルが必要な場合**は、CC0配布元の個別アセットページとライセンスを確認してから取得する。
5. 既存の完成モデルを削除・置換せず、追加造形・別モジュールとして品質を上げる。

- 第2層の詳細な候補と収集台帳: `docs/3d/B2_CC0_ASSET_SOURCES.md`（PR #324で提案中。未マージなら当該ブランチ参照）。
- Pinterest画像は**造形の参考**。権利未確認の画像を再配布・ゲームに同梱しない。
- 『ゼルダの伝説 ブレス オブ ザ ワイルド』などの商用ゲームは造形の考え方や雰囲気の研究に限る。ゲーム内モデルやテクスチャをCC0とみなさない。

## 取得・記録のルール
1. 目的に合う候補を選び、実ファイルの取得可否を確かめる。
2. アセット単位で名称、配布元URL、ライセンスURL・表記、確認日、ファイル形式、容量、SHA256、改変内容、採用先を記録する。
3. ライセンスが曖昧な素材、Pinterest画像、商用ゲーム由来のデータはCC0保存フォルダへ入れない。
4. Blenderで実際に読み込み、正面・側面・斜めをレンダリングする。生成処理成功と画像の目視確認を区別する。
5. GLB/PNGをユーザーが品質確認・承認した後、正式素材フォルダへ昇格する。GitHub Actions Artifactsは一時保存場所。
6. 変更は独立ブランチと `development` 向けPRで管理する。`main` を勝手に更新しない。

## 造形・配置の品質基準
- テクスチャより**大きなシルエット、厚み、破断面、部材の接続と配置**を優先する。
- 規則的な反復・機械的な凸凹を避け、意図のある大小差と非対称性を付ける。
- マス単位のランダムマップ用モデルは、接続端の高さ・幅・方向を揃え、破損や装飾は接続面から離す。
- CC0素材の形状をそのまま貼り付けるだけでなく、階層のテーマ・視点・縮尺に合わせて加工する。
- 画像を取得できなかった場合は、見たことにせず未確認と記録する。

## 階層別の参照例
- **1層 樹海:** 木・根・岩・草・苔・森林遺跡
- **2層 水源/氷:** 石橋・水路・氷柱・浸食された石材・凍結岩盤
- **3層 遺跡都市:** 崩壊建築・鉄骨・瓦礫・雑草・都市インフラ
- **4層 溶岩/炭鉱:** 岩盤・鉱石・廃坑設備・炭化した木・溶岩亀裂
- **5層 魔王城:** ゴシック石材・アーチ・柱・彫刻・崩落天井
- **6層 花園:** 草葉・花・自然岩・密度のある植生
