# 仲間所持・控え管理 実装メモ

## 今回の実装
- `state.ownedCharacters` を所持仲間IDの一覧として追加。
- `state.party` は従来どおり戦闘参加メンバーのみを保持。
- 所持上限は10人、戦闘参加上限は既存の `PARTY_LIMIT=5` を使用。
- 編成画面に控えメンバー一覧を追加。
- 所持仲間全員へ戦闘経験値を配布。戦闘参加中に戦闘不能だったメンバーは従来どおり経験値対象外、控えメンバーはHPに関係なく対象。
- 主人公（kotama）はSTAGE 5クリア記録 `stageCleared[5]` が付くまで控えへ移動できない。
- セーブバージョンを11に更新。旧セーブは従来の `state.party` を所持仲間として補完する。

## 重要な現状制約
現在の `data/characters.js` は「仲間個体」ではなく、職業ごとに1つの固定キャラクターID（kotama / knight / healer / warrior / mage / samurai）を持つ構造。
そのため、今回の実装で所持枠10人のデータ上限は設けたが、現行データだけで10人の異なる仲間を作成・加入させることはできない。自由作成キャラクターを含む10人編成を完成させるには、職業テンプレートと仲間個体を分離し、個体ごとの一意IDでレベル・経験値・装備・スキル・HP/SP等を管理する後続のデータモデル移行が必要。

この後続作業では、Claude Aの職業変更機能と競合しないよう、職業IDと仲間個体IDの責務を先に合意すること。
