# 職業変更システム 実装メモ（Claude A）

- 関連：Issue #28、仕様 `docs/ai-tasks/CLAUDE_A_JOB_CHANGE_IMPLEMENTATION.md`（`docs/claude-development-specs` ブランチ）
- 本体：`job.js`（新規）、`css/08-job-change.css`（新規）
- 接続：`script.js`・`battle-ext.js`・`analyze-panel.js`・`index.html` の `[JOB]` の目印の行だけ

## 1. データ構造：個体と職業の分離

現行コードでは、キャラクターID（`c.id`）が「個体」と「職業」を兼ねています。`c.id` を書き換えると、ID をキーにしている成長データ（Lv・経験値・装備・育成値・スキルツリー・育成ポイント）がすべて別人のものになるため、**`c.id` は一切変更しません**。

| 区分 | 持ち方 | 中身 |
|---|---|---|
| 個体 | 従来どおり `c.id`（例：`kotama`） | 名前・画像、`characterLevels`・`levelExp`・`equipment`・`growth`・`skillLevels`・`unlockedSkills`・`legacyTreeBonuses`・`trainingPoints`・ユニオン |
| 職業 | **新規** `characterJobs[個体ID] = 職業ID` | 未設定なら個体ID＝職業ID（従来どおり） |
| 職業テンプレート | `jobTemplates()` | 起動直後の各キャラクターの素データ（＝その職業の基礎値）。最初に呼ばれた時点で控える |

職業を変えると、テンプレートの次の項目を個体に写します（`jobApplyTemplate`）。

`maxHp`・`attack`・`spAttack`・`defense`・`spDefense`・`guardCut`・`maxSp`・`spSkills`・`speed`

`spDefense` を持たない職業では項目ごと削除し、防御力から算出する従来の扱いに戻します。

- 職業ID の一覧：基本6職業（`kotama`=冒険者、`knight`、`healer`、`warrior`、`mage`、`samurai`）と、新職業6種（`EXT_NEW_JOBS`）。
- 解放済みの職業：基本6職業は常に解放。新職業は既存の `state.unlockedJobs`（ステージクリア・隠しボス討伐）に従います。**解放条件は変更していません。**
- 個体の現在の職業は `jobOf(c)`（`script.js` では `characterJobId(c)`）で取得します。

## 2. レベルと経験値

- 変更後のレベルは `max(1, 現在Lv − 5)` です。
- **レベル内の経験値（`levelExp`）は0に戻します。** `level.js` ではレベル（`characterLevels`）が正本で、`levelExp` は「そのレベル内で貯まっている経験値」です。必要経験値（`levelExpToNext`）はレベルとともに増えるため、高レベル時の端数を低レベルへ持ち込むと、次の戦闘で即座にレベルアップしてしまいます。それを避けるための扱いです。
- 能力値のレベル成長（`levelApplyStats`）は「個体の基礎値 × 成長率 ×（Lv−1）」なので、テンプレートを写すことで自動的に新しい職業の基礎値から計算されます。
- 獲得済みの育成ポイント（`trainingPoints`）は減らしません（判断事項 D-3）。

## 3. 能力値

- 基礎値：職業テンプレートの値。
- 職業補正（`BATTLE_RULES.classBonuses`）：**新しい職業のもの**を使います（`effectiveStats` を `characterJobId(c)` に変更）。
- 育成値（`growth`）・装備補正・スキルツリーの基礎パッシブ補正：個体のまま引き継ぎます。
- 現在HP・SPは割合を保ちます。戦闘不能の個体は0のままです。

## 4. 装備

- 装備適性（`item.classes`）は、**新しい職業の ID** で判定します。対象は装備変更時の確認、ショップの絞り込み・購入可否、`isSkillRestricted`（適性外装備でSP・ユニオンが封じられる判定）です。
- 装備枠は職業で決まります（武士は刀2本、それ以外は武器1つ。`equipmentSlots`）。
- 変更時、次の装備は**外して所持品に戻します（消失なし）**。
  - 新しい職業に無い枠の装備（例：武士→騎士の刀）
  - 新しい職業に適性の無い装備
- 外れる装備は、確認ダイアログに事前に表示します。

## 5. スキル

- 職業のSPスキル（`c.spSkills`）は、新しい職業のものに切り替わります。
- スキルツリー（`skillTreeDefinitions[c.id]`・`skillLevels`）は**個体に紐づいたまま**です。習得済みのツリースキルは転職後も使えます（判断事項 D-1）。
- ユニオンスキル（`unionSkills[c.id]`）も個体のままです（判断事項 D-2）。

## 6. セーブ／ロード

- `createSaveData` に `characterJobs`（本来と違う職業の個体だけ）を追加しました。`saveVersion` は 10 のまま、項目の追加だけです。
- `loadGame` では、能力値を使う処理（`combatants` のHP復元）より前に `jobDeserialize` で職業を適用します。
- **旧セーブ**（`characterJobs` なし）は、全員が本来の職業のまま読み込まれます。
- 未知の職業・未解放の職業が保存されていた場合は無視し、本来の職業に戻します。
- 戦闘開始時のスナップショットも `createSaveData` を使うため、職業が含まれます。

## 7. 画面

- 育成画面の下に「職業変更」セクションを追加しました（`renderProgressionPanel` から `jobRenderSection`）。
  - 対象キャラクターの選択（解放済みの全キャラクター）
  - 現在の職業とレベル
  - 変更先の職業ボタン
- 確認ダイアログの内容：
  - 変更前後のレベル・最大HP・攻撃力・防御力・SP攻撃力・SP防御力・最大SP・素早さ・SPスキル
  - 外れる装備
  - 失われるレベル内経験値
- キャンセル・Esc・背景クリックで閉じます。データは確定時にだけ変わります。
- 「変更する」は開いてから400ms後に押せるようになります（PR #26 の A-01 で見つかった連打誤操作の対策）。
- 戦闘中・チュートリアル中は変更できません。
- 確定後はオートセーブします（`persistAutoSave`）。
- ホーム画面からの導線と、細かな見た目の調整は未対応です（今回の優先順位に従い、骨組みを優先）。

## 9. 確認したこと（骨組みの範囲）

Chrome（Playwright）で、以下を確認しました。網羅的な動作検証は今回の範囲外です。

- 育成画面にセクションが表示され、変更先として解放済みの職業だけが並ぶ。
- 未解放の職業（例：アサシン）は拒否される。
- コタマ Lv.10 → 魔術師：Lv.5、レベル内経験値0、能力値・SPスキル（ファイア・フリーズ・サンダー）・最大SP・素早さが魔術師のものになる。剣は所持品に戻る。
- セーブ→再読み込み後も職業・能力値が保たれる。
- 旧形式のセーブ（`characterJobs` なし）が読み込める。
- Lv.3 → Lv.1（下限）。武士への変更で装備枠が刀2本になる。元の職業に戻すと `characterJobs` から消える。
- 新職業の個体（アサシン）も転職できる。
- 転職した個体が戦闘で新しい職業のSPスキル（ファイア・毒刃）を使える。戦闘中は変更できない。
- コンソールエラー0件。
