## 1. しくみ

各階層の 1F・2F に「調べられる物」を1つずつ置きました。3F の既存 NPC には「届ける・渡す」イベントを付け、**全15フロアに探索の目的**があります。

| 部品 | 場所 | 内容 |
|---|---|---|
| 調べられる物 | `FIELD_AREAS[n].objects` の `kind:"event"`（文字 `c`＝1F、`d`＝2F） | 既存の NPC と同じく、マップ上の英小文字で置く。通れない。正面で調べる |
| NPC の追加イベント | 既存 NPC の `sideEvents: [ID]` | いつもの会話のあとに、未達成のイベントを1つだけ進める。既存の会話はそのまま流れる |
| イベント定義 | `data/field-maps.js` の `FIELD_SIDE_EVENTS` | `scene`／`doneScene`／`requires`＋`hintScene`／`needs`＋`askText`＋`needText`／`reward`／`keyItem` |
| 会話 | `data/story.js` の `side-*` シーン | 既存の会話形式（`who`・`ifParty`）。`once` は使わない |
| 処理 | `field.js` の `[SIDE]` 節 | `fieldRunSideEvent`・`fieldRunNpcSideEvents`・報酬付与・フラグ |
| 隠し発見 | オブジェクトの `hidden:true` | ラベルなし。かすかなきらめきだけで、正面に立つと A ボタンが光る。ミニマップには発見するまで出ない |

### 処理の流れ（`fieldRunSideEvent`）
1. 完了済み（`fieldState.flags["side:<ID>"]`）なら、`doneScene` か「もう何も見つからない。」を出す。NPC 経由のときは何も出さない。
2. `requires` が未達成なら `hintScene` を流す（探索の目的を伝える）。
3. `needs` があれば、素材が足りるか確認する。足りなければ `needText`（必要数と所持数）を出す。足りれば「渡す／やめる」を聞き、渡すときだけ素材を減らす。
4. **先に完了フラグを立ててから**報酬を渡し、オートセーブする。そのあと `scene` と入手メッセージを出す。会話中の二重実行や、保存のタイミングによる再取得を防ぐため。
5. `field:side:complete` イベントを発行する（他の機能から拾えるように）。

### セーブ
- 新しい保存項目はありません。既存の `fieldState.flags` に `side:<ID>` を `true` で追加するだけです（`fieldSerialize` がそのまま保存する）。旧セーブはフラグが無いだけなので、全イベントが未達成として読み込まれます。
- マップは、各フロアの行き止まり1マスを英小文字に置き換えただけで、サイズは変わっていません。踏破マップ（`explored`）・宝箱の順番（`chests`）・FOE の巡回路はそのままです。
  - 置き場所は「すべての階段・出口・ボスゲート・宝箱・採取ポイント・灯・看板・NPC に、開始位置から近づける」ことをスクリプトで確認したマスだけです。FOE の巡回点とは重ならないようにしています。
  - 保存位置がちょうどそのマスだった旧セーブは、既存の処理（`fieldBoxBlocked` のチェック）で開始位置から再開します。

### 報酬の決め方
- 既存の宝箱の中身（各階層 1F〜3F）と同じくらいの規模にしました。目安は第1階層 30〜80G、第5階層 400〜500G です。届けるイベントは、2〜3か所を回る分だけ少し多めにしています。
- アイテムは既存の消耗品（回復薬・上級回復薬・SPエーテル）だけ、素材は既存の `materials` だけを使いました。新しい通貨・アイテムは追加していません。
- 「だいじなもの」は表示だけで、インベントリには入りません（完了フラグで管理）。

## 3. 既存仕様との関係
- 既存 NPC の会話（`a1-woodcutter` など）は、シーン ID も文章も変えていません。追加イベントは、その会話のあとに続けて流れます。
- 霧の森の石像（`a3-statue`・ボスゲートの条件 `gateRequires`）は変わりません。石像の追加イベントは、`a3-statue` の会話が終わったあとにだけ進みます。
- 既存の看板（`?`）・宝箱（`T`）・採取（`G`）・灯（`S`）の処理には触れていません。
- 見た目は仮の絵文字（`css/07-labyrinth.css` の `[SIDE]` 節）です。GPT が絵を付ける場合は、`data-sprite`（`ev-stump`・`ev-crate`・`ev-shard`・`ev-bag`・`ev-emblem`・`ev-sword`・`ev-hidden`）ごとに差し替えてください。
- 全体マップの凡例に「発見」を追加しました（水色。完了後は灰色）。

## 4. 新しいサブイベントの足し方
1. `FIELD_SIDE_EVENTS` に ID と定義を追加する。
2. `data/story.js` に `side-...` の会話を追加する。
3. 調べる物なら、`FIELD_AREAS[n].objects` に `kind:"event"` の文字を追加し、マップの行き止まりに置く。NPC なら `sideEvents` に ID を足す。
4. 置き場所は、すべての階段・宝箱などに近づけるマスにする（通路をふさがない行き止まりを使う）。

## 5. 確認したこと（最小限）
- 参照チェック（スクリプト）：全イベントの会話シーン・前提イベント・素材・消耗品の ID が存在する。各文字が1フロアにだけある。全15フロアで、階段・宝箱・採取・NPC などに近づける。
- ブラウザで、第1階層の全イベントと第4階層の鉱脈、第5階層の連鎖を実行した。確認できたこと：
  - ヒント → 発見 → 届ける、の順に進む。
  - 2回目は空振りする。
  - 素材が足りないと理由を表示し、足りれば素材を減らして報酬を渡す。
  - 報酬は1回だけ。
  - セーブ → 読み込みで完了フラグが残る。
  - JS エラーなし。
- 指示書のとおり、網羅的な回帰テストは行っていません。

## 6. ユーザー・GPT に確認したいこと
- 報酬の量（特に第5階層の 500G＋回復アイテム）が強すぎないか。
- 仮の絵文字を、正式な絵に差し替えるかどうか。
- 「だいじなもの」を一覧で見られる画面が必要か（今回は作っていない。必要なら `side:` フラグから一覧を作れる）。
