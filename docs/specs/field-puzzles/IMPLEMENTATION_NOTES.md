## 1. しくみ

前回の `FIELD_SIDE_EVENTS` とは分けて、**仕掛け専用の定義 `FIELD_PUZZLES`** と、専用のオブジェクトの種類を設けた。

| 種類（`objects` の `kind`） | 役割 | 置く場所 |
|---|---|---|
| `switch` | スイッチ（レバー・合図石・石灯籠・騎士像） | `onWall:true`：**壁のマス**に置く。通れる場所は変わらない。通路側から正面で調べる |
| `door` | 扉。解けるまで通れない。開くと床になる | 行き止まりの枝道の入口（通路のマス） |
| `door` + `hidden:true` | 隠し通路。開くまでは壁に見え、視界もさえぎる | 同上 |
| `cache` | 扉の奥の報酬（宝箱相当） | 枝道のいちばん奥 |
| `sign`（文字で置く） | ヒントの立て札・石碑。既存の看板と同じ処理で `scene` を流す | 壁のマス（`onWall:true`） |

| `FIELD_PUZZLES` の `type` | 解き方 | 途中経過 |
|---|---|---|
| `lever` | スイッチ1つで開く | — |
| `all` | すべてのスイッチを入れる（順番は自由） | 入れたスイッチは保存する |
| `order` | `order` の順に入れる。間違えると最初から | 保存しない（フロアを出ると最初から） |
| `hidden` | 扉そのものを調べて開ける | — |

### 処理（`field.js` の `[PUZZLE]` 節）
- `fieldCharSolid(a, c)`：扉の文字は、解けるまで壁扱いにする。`fieldSolidAt`（プレイヤーの当たり判定）と `fieldFoeWalkable`（FOE の経路）の両方がこれを使う。
- `fieldWallLike(a, c)`：壁に付いた物と開く前の隠し通路を、壁として描画・ミニマップ表示し、視界（`fieldOpaque`）もさえぎる。
- `fieldPuzzleInteract(o)`：スイッチ・扉・宝箱を調べたときの処理。
  - スイッチは毎回「はい／いいえ」で確認する。
  - 解決済みの仕掛けは、「仕掛けはもう動いている」と出すだけで再操作できない。
  - 宝箱は**先にフラグを立ててから**報酬を渡し、オートセーブする（二重取得の防止）。
- `fieldPuzzleSolve(id)`：解決フラグを立ててオートセーブし、扉のタイル・視界・ミニマップを更新して、`solveScene` を流す。DOM を作り直さないので、FOE の位置はそのまま。
- 扉が開いたら、調べる対象から外れて通れるようになる（`fieldFacingObject`）。
- イベント通知：`field:puzzle:solve`、`field:puzzle:reward`。

### 保存
すべて既存の `fieldState.flags` に `true` で追加するだけ（`fieldSerialize` がそのまま保存する）。

| フラグ | 意味 |
|---|---|
| `puzzle:<ID>` | 解決済み（扉が開いている） |
| `puzzle:<ID>:reward` | 扉の奥の宝箱を開けた |
| `puzzle:<ID>:sw:<スイッチID>` | `all` 型で、そのスイッチを入れた |

- 旧セーブにはフラグが無いので、すべて未解決として読み込まれる。
- 読み込み時の位置チェック（`fieldBoxBlocked`）は、フラグを読み込んだあとに行われるため、開いた扉の上・扉の奥で保存した位置もそのまま復元される。
- 保存位置がちょうど閉じた扉のマスだった旧セーブは、既存の処理で開始位置から再開する。

- **総当たりはさせない設計にした。** どの仕掛けも、扉の目の前か隣にヒントがあり、扉を調べるとヒントを読むよう促される。順番の仕掛けは、間違えた時点で「石碑を読み返そう」と表示して最初から戻る。
- 報酬は既存のゴールド・消耗品・素材だけ。任意攻略で手間がかかる分、各階層の宝箱より少し多め（同じ階層の届けるイベントと同じくらい）にした。

## 3. 既存マップ・イベントとの干渉確認（スクリプト `verify_puzzles` 相当）
全15フロアについて、次を確認した。
- **扉を閉じた状態で**、開始位置から次のすべてに近づける：階段・出口・ボスゲート・宝箱・採取ポイント・導きの灯・看板・NPC・**前回のサブイベント**・スイッチ・ヒント。扉の奥の宝箱だけは近づけない（意図どおり）。
- **扉を開けた状態で**、奥の宝箱に近づけ、扉を閉じていたときに行けた場所はそのまま行ける。
- 扉の奥（枝道）は、もともと何も無い行き止まりの通路。扉の奥のマス数は、第1・第2階層が 3、第3〜第5階層が 11。
- FOE の巡回点は、どれも塞いでいない。扉と枝道は FOE の巡回路の外にある。
- スイッチ・ヒントは壁のマスに置いたので、通れる場所は一切変わらない。マップサイズ・開始位置・宝箱の順番（`chests`）・踏破マップの長さは変わらない。
- 参照チェック：仕掛けの ID・オブジェクト ID・マップ文字が重複していない（各文字が1か所だけ）。扉と宝箱は仕掛けごとに1つずつ、スイッチは定義と配置が一致し、`order` は `switches` の中から選んでいる。全オブジェクトが同じフロアにある。会話シーン・話し手・報酬のアイテム・素材 ID が存在する。サブイベントの ID とも重複していない。

## 4. ブラウザで確認した範囲（最小限）
5つの仕掛けすべてを、ゲーム内の関数で操作して確認した。
- 扉を調べるとヒントが出る。スイッチで「いいえ」を選ぶと何も変わらない。
- 解く前の扉は通れない（当たり判定・FOE の経路とも）。解いた後は通れる。
- `all` 型は1つ目で 1/2 と表示され、同じスイッチは再操作できず、2つ目で開く。
- `order` 型は、間違えると途中経過が消えて最初から。正しい順で開く。
- 隠し通路は、開く前は壁に見えて視界をさえぎり、開くと床のタイルに変わる。
- 宝箱は1回だけで、2回目は空。解決後のスイッチは再操作できない。
- 保存 → 再読み込みで、解決と報酬のフラグが残り、扉は開いたまま。JS エラーなし。

網羅的な回帰テストは指示どおり行っていない。

## 5. 他担当への連絡事項
- `script.js` などの他担当ファイルを変更する必要はなかった。
- 見た目は仮の絵文字（`css/07-labyrinth.css` の `[PUZZLE]` 節）。GPT が絵を付ける場合は、`data-sprite`（`pz-lever`・`pz-bell`・`pz-lantern`・`pz-statue`・`pz-door`・`pz-mist-door`・`pz-crack`・`pz-cache`・`pz-plaque`）と状態クラス（スイッチ `is-on`、扉 `is-open`、隠し通路 `is-hidden-door`、宝箱 `is-opened`）ごとに差し替えてほしい。
- 全体マップの凡例に「仕掛け」（桃色の四角）を追加した。閉じた扉は茶色、宝箱は橙色で表示する。
